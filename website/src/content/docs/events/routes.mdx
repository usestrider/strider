## Declarations

A declaration is a setting held for a scope: a route, an init script, the page clock, an emulated setting, a
granted permission, a dialog or file chooser handler.

- The browser confirms it before the call returns, so it applies from the next line.
- It's removed when its scope closes, or earlier with its handle's `remove`.

## Routes

`page.route(pattern, handler)` sends each matching request to the handler before it leaves the browser. The handler
returns a decision, built from Effect's HTTP types in `effect/http`:

```ts
import { Page, Route } from "@usestrider/browser"
import { Effect } from "effect"
import { HttpClientRequest, HttpServerResponse } from "effect/http"

const fakeBackend = Effect.fn("fakeBackend")(function*(page: Page.Page) {
  yield* page.route(
    "https://app.example.com/api/user",
    () => Effect.succeed(Route.fulfill(HttpServerResponse.jsonUnsafe({ name: "Ada" })))
  )
  yield* page.route(
    "https://app.example.com/api/**",
    () => Effect.succeed(Route.continueWith(HttpClientRequest.setHeader("x-test", "1")))
  )
  yield* page.route("**/analytics/**", () => Effect.succeed(Route.abort()))
  yield* page.goto("https://app.example.com")
})
```

| Decision                    | What happens to the request                                              |
| --------------------------- | ------------------------------------------------------------------------ |
| `Route.fulfill(response)`   | answered with `response`; it never reaches the server                    |
| `Route.continueWith(change)` | sent on, changed: a function of Effect's `HttpClientRequest`             |
| `Route.continue`            | sent on as it is                                                         |
| `Route.abort(reason?)`      | fails, as a network error would                                          |
| `Route.fallthrough`         | asks the next route that matches, or lets the request continue           |

- A pattern is a glob, a URL or a `URLPattern`.
- The page's routes are asked before its context's, the newest first; `fallthrough` passes to the next.
- A route's handle counts the requests it was asked about in `hits`, a watchable number.
- A handler that fails, is interrupted or times out lets the request continue. The failure is logged and reported
  as an `AutoResolution` event.

## The response phase

With `{ phase: "response" }`, the handler sees the server's status and headers, and can pass the response on
changed or replace it. The phase types what the handler gets and returns, so a decision that doesn't fit the phase
doesn't compile:

```ts
import { Page, Route } from "@usestrider/browser"
import { Effect } from "effect"

const markResponses = Effect.fn("markResponses")(function*(page: Page.Page) {
  yield* page.route(
    "https://app.example.com/api/**",
    (intercepted) => {
      const headers = { ...intercepted.response.headers, "x-seen": "1" }
      return Effect.succeed(Route.continueWith({ headers }))
    },
    { phase: "response" }
  )
})
```

- Changing status and headers: Chromium and Firefox.
- Reading `intercepted.responseBody` and fulfilling with a patched copy: Chromium only.
- WebKit does neither.

`{ phase: "auth" }` answers an HTTP authentication challenge, on Chromium and Firefox:

```ts
import { Page, Route } from "@usestrider/browser"
import { Config, Effect } from "effect"

const signInToStaging = Effect.fn("signInToStaging")(function*(page: Page.Page) {
  const password = yield* Config.Redacted("STAGING_PASSWORD")
  yield* page.route(
    "https://staging.example.com/**",
    () => Effect.succeed(Route.provideCredentials({ username: "ada", password })),
    { phase: "auth" }
  )
  yield* page.goto("https://staging.example.com")
})
```

## Replaying a recording

`Route.fromHar` reads a HAR file, from `Har.record` or another tool, and makes a handler that answers each request
from the entry matching its method, URL and body:

```ts
import { Page, Route } from "@usestrider/browser"
import { Effect } from "effect"

const fromRecording = Effect.fn("fromRecording")(function*(page: Page.Page) {
  const replay = yield* Route.fromHar("./fixtures/api.har")
  yield* page.route("https://shop.example.com/api/**", replay)
  yield* page.goto("https://shop.example.com/cart")
})
```

- A request with no entry is aborted, unless `{ notFound: "fallthrough" }`.
- Reading the file needs Effect's `FileSystem`. Build the backend's layer with
  `Layer.provideMerge(NodeServices.layer)` instead of `Layer.provide`, so the program gets it too.

## Init scripts

`addInitScript` runs a function at the start of each new document, in every frame, before the page's own scripts:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const installHooks = () => {
  Object.assign(window, { __clicks: [] as Array<string> })
}

const recordClicks = () => {
  const clicks = (window as unknown as { __clicks: Array<string> }).__clicks
  addEventListener("click", (event) => clicks.push((event.target as Element).tagName))
}

const testHooks = Effect.fn("testHooks")(function*(page: Page.Page) {
  const hooks = yield* page.addInitScript(installHooks)
  yield* page.addInitScript(recordClicks, { after: [hooks] })
  yield* page.goto("https://app.example.com")
})
```

- The function crosses into the page, so it must be self-contained.
- The context's scripts run before the page's, each in the order added.
- With `after`, a script runs only if each script it names ran in that document without throwing.
- A script that throws is reported as an `UncaughtException`.
- `world: "isolated"` runs it apart from the page's scripts. `workers: true` also runs it in dedicated workers, on
  Chromium and WebKit.
- Added to a loaded page, it runs from the next document.

## The page clock

`page.clock` replaces `Date`, `performance.now` and timers with a clock you stop, set and move:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const sessionExpires = Effect.fn("sessionExpires")(function*(page: Page.Page) {
  yield* page.clock.install({ mode: "controlled", at: "2026-01-01T09:00:00Z" })
  yield* page.goto("https://app.example.com/session")
  yield* page.getByRole("button", { name: "Start" }).click()
  yield* page.clock.adjust("5 minutes")
  yield* page.getByText("Session expired").pipe(Expect.toBeVisible)
})
```

| Mode         | Wall time                 | Timers and animation frames    |
| ------------ | ------------------------- | ------------------------------ |
| `fixed`      | frozen at `at`            | run in real time               |
| `offset`     | shifted `by` a duration   | run in real time               |
| `controlled` | starts at `at`, moves only when told | run only when time moves |

- `adjust` moves a controlled clock forward, firing each timer that comes due, in order.
- `setTime` jumps, firing due timers at most once, as a laptop waking from sleep.
- `resume` returns to real time from where the clock stands.
- One timeline spans the page's documents and frames; navigating doesn't reset it.
- The page clock doesn't touch Strider's deadlines, and `TestClock` doesn't touch the page.
