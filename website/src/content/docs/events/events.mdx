An action's effects, such as a popup or a download, can arrive before the action returns, so a program that looks
for them afterwards can miss them. A subscription made before the action sees everything the action causes.

## Subscribing before acting

`Download.next` subscribes when it's called and gives a wait, an `Effect` of the first matching download, so call
it before the action:

```ts
import { Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const exportCsv = Effect.fn("exportCsv")(function*(page: Page.Page) {
  const download = yield* Download.next(page) // subscribed from here on
  yield* page.getByRole("button", { name: "Export CSV" }).click()
  const file = yield* download // the first download since
  yield* file.saveAs("./export.csv")
})
```

Subscribing after the click is a race. If the download came first, the wait times out with a hint: "a download
came 12 ms before Download.next subscribed; call Download.next before the action that causes it".

## Next, stream and history

Each kind of event is a module with three functions. Use `next` for the one event an action causes, `stream` to
watch every event for a while, such as console errors, and `history` to read what happened before you looked.
Dialogs and file choosers also have [`handle`](#dialogs):

| Verb      | Does                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| `next`    | subscribes now; its value is a wait for the first match                                       |
| `stream`  | subscribes now; gives a `Stream` of every match from then on                                  |
| `history` | reads the matches already logged, and never waits                                             |
| `handle`  | dialogs and file choosers: registers a function that decides each one until its scope closes  |

A filter is data, applied before events are buffered, so the events it rejects never count toward the 1,000 events a
stream holds for a slow consumer ([Streams](#streams)). `where`, after the filter, adds a predicate for anything a filter can't say: it gets the event and returns an
`Effect` of a boolean:

```ts
import { Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const downloadInvoice = Effect.fn("downloadInvoice")(function*(page: Page.Page) {
  const invoice = yield* Download.next(
    page,
    { url: "**/invoices/**" },
    (download) => Effect.succeed(download.suggestedFilename.endsWith(".pdf"))
  )
  yield* page.getByRole("link", { name: "Download invoice" }).click()
  const file = yield* invoice
  yield* file.saveAs(`./invoices/${file.suggestedFilename}`)
})
```

## Event modules

| Module              | Reports                                                     | Filter                             |
| ------------------- | ----------------------------------------------------------- | ---------------------------------- |
| `PageNavigation`    | navigations of the page, and optionally its frames           | `url`, `frames`, and `waitUntil` for `next` |
| `Popup`             | pages this page opened                                       | `url`                              |
| `Dialog`            | alerts, confirms, prompts and `beforeunload`                 | `kind`                             |
| `FileChooser`       | file pickers the page opened                                 | `multiple`                         |
| `Download`          | downloads                                                    | `url`                              |
| [`NetworkRequest`](/docs/events/network) | requests, one per redirect hop                               | `url`, `method`, `resourceType`    |
| [`NetworkResponse`](/docs/events/network) | responses, with their bodies when asked                      | `url`, `method`, `status`, `body`  |
| `ConsoleMessage`    | console output                                               | `level`, `text`                    |
| `UncaughtException` | errors nothing caught, and rejections nothing handled        | `message`                          |
| [`BrowserWorker`](/docs/api/browser/BrowserWorker) | workers the page or context started                          | `url`, `kind`                      |
| [`NetworkConnection`](/docs/api/browser/NetworkConnection) | WebSockets and event sources, with their frames               | `url`, `kind`                      |
| [`AutoResolution`](/docs/api/browser/AutoResolution) | dialogs, choosers and requests decided by a default          | `subject`                          |

## Navigations

[`Expect.toHaveURL`](/docs/pages/expectations#expectations) says where the page is, not what got it there. `PageNavigation.next` gives the navigation the
action caused, with its response, so an error page or a same-document change can be told apart:

```ts
import { Page, PageNavigation } from "@usestrider/browser"
import { Effect, Option } from "effect"

const openOrders = Effect.fn("openOrders")(function*(page: Page.Page) {
  const orders = yield* PageNavigation.next(page, {
    url: "**/orders",
    waitUntil: "load"
  })
  yield* page.getByRole("link", { name: "Orders" }).click()
  const navigation = yield* orders
  if (navigation._tag !== "Committed") return Option.none()
  return Option.map(navigation.response, (response) => response.status)
})
```

The navigation is data: `Committed` with its response, `SameDocument` for a fragment or the History API, `Restored`
from the back/forward cache, and [others](/docs/api/browser/PageNavigation#PageNavigation). `waitUntil: "load"` also waits for the document to load.

## Popups

`Popup.next` gives a page the page opened, as a `Page` that closes with its opener's scope:

```ts
import { Dialog, Page, Popup } from "@usestrider/browser"
import { Effect } from "effect"

const connectAccount = Effect.fn("connectAccount")(function*(page: Page.Page) {
  const popups = yield* Popup.next(page)
  yield* page.getByText("Connect account").click()
  const popup = yield* popups
  yield* Dialog.handle(popup, Dialog.acceptAll)
  yield* popup.getByRole("button", { name: "Allow" }).click()
})
```

Here [`Dialog.handle`](#dialogs) accepts every dialog the popup opens. The popup is reported before its first
document loads, so a handler or route registered on it applies to that
document.

On Chromium, a popup's opener stops rendering, and actions on it time out with a hint saying so. Call
`yield* page.activate` ([reference](/docs/api/browser/Page#Page.activate)) first, or make the context with
[`focus: "emulated"`](/docs/tools/testing#concurrent-pages). Firefox and WebKit keep rendering it.

## Dialogs

A dialog blocks its page until it's decided, and the action that opened it doesn't return until then, so a wait
collected after the action would come too late. Register a handler before it opens; the handler lasts until its
scope closes:

```ts
import { Dialog, Page } from "@usestrider/browser"
import { Effect } from "effect"

const deleteAccount = Effect.fn("deleteAccount")(function*(page: Page.Page) {
  yield* Dialog.handle(page, (dialog) => {
    switch (dialog._tag) {
      case "Confirm": {
        const yes = dialog.message.includes("delete")
        return Effect.succeed(yes ? dialog.accept : dialog.dismiss)
      }
      case "Prompt":
        return Effect.succeed(dialog.respond("DELETE"))
      case "Alert":
        return Effect.succeed(dialog.accept)
      case "BeforeUnload":
        return Effect.succeed(dialog.leave)
      case "Unknown":
        return Effect.succeed(dialog.accept)
    }
  })
  yield* page.getByRole("button", { name: "Delete account" }).click()
})
```

- Each kind offers only its own decisions: an alert can only be accepted, a prompt can be answered.
- `Dialog.acceptAll` and [`Dialog.dismissAll`](/docs/api/browser/Dialog#dismissAll) are ready-made handlers.
- A dialog no handler decides goes to the context's
  [`dialogs` policy](/docs/pages/contexts#settings-for-the-whole-session), `"dismiss"` by default, at once. Each
  such decision is reported as an `AutoResolution` event.

File choosers work the same way. A chooser no handler answers is canceled, and reported:

```ts
import { FileChooser, FileInput, Page } from "@usestrider/browser"
import { Effect } from "effect"

const uploadPhoto = Effect.fn("uploadPhoto")(function*(page: Page.Page) {
  yield* FileChooser.handle(page, FileChooser.choose(FileInput.local("./photo.jpg")))
  yield* page.getByRole("button", { name: "Upload photo" }).click()
})
```

The decisions a default made are events too, so a flow can report the dialogs nothing handled:

```ts
import { AutoResolution, Page } from "@usestrider/browser"
import { Effect } from "effect"

const undecidedDialogs = Effect.fn("undecidedDialogs")(function*(page: Page.Page) {
  const decided = yield* AutoResolution.history(page, { subject: "Dialog" })
  for (const { subject, decision } of decided.entries) {
    if (subject._tag === "Dialog") {
      yield* Effect.logWarning(`${subject.kind} "${subject.message}" was ${decision}`)
    }
  }
})
```

## Downloads

A download's event comes when it starts, before its file is complete. The handle, with its file, status and
suggested name, follows it to the end, so you save or read the file once it's whole:

```ts
import { Download, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const exportReport = Effect.fn("exportReport")(function*(page: Page.Page) {
  const pdf = yield* Download.next(page)
  yield* page.getByText("Export PDF").click()
  const report = yield* pdf
  yield* report.status.changes.pipe(
    Stream.runForEach((status) => Console.log(status._tag)),
    Effect.forkScoped
  )
  yield* report.saveAs(`./reports/${report.suggestedFilename}`)
})

const exportedHeader = Effect.fn("exportedHeader")(function*(page: Page.Page) {
  const csv = yield* Download.next(page)
  yield* page.getByRole("button", { name: "Export CSV" }).click()
  const text = yield* (yield* csv).stream.pipe(Stream.decodeText(), Stream.mkString)
  return text.split("\n")[0]
})
```

- The file is kept in a directory the context owns, and removed with it.
- `saveAs` copies it out once complete; `stream` gives its bytes; `finished` waits for it to end.

## Several outcomes

Subscribe to each before the action, then collect them together:

```ts
import { NetworkResponse, Page, Popup } from "@usestrider/browser"
import { Effect } from "effect"

const pay = Effect.fn("pay")(function*(page: Page.Page) {
  const checkout = yield* Popup.next(page)
  const order = yield* NetworkResponse.next(page, { url: "**/api/order" })
  yield* page.getByRole("button", { name: "Pay" }).click()
  const [tab, placed] = yield* Effect.all([checkout, order])
  return { tab, status: placed.status }
})
```

A wait keeps its event from when it arrived. Running it again gives the same event.

## Streams

`stream` gives every match from when it subscribes. Fork its consumer into the scope to watch in the background:

```ts
import { ConsoleMessage, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const logErrors = Effect.fn("logErrors")(function*(page: Page.Page) {
  const errors = yield* ConsoleMessage.stream(page, { level: "error" })
  yield* errors.pipe(
    Stream.runForEach((message) => Console.error(`[page] ${message.text}`)),
    Effect.forkScoped
  )
})
```

- A stream ends when its page closes, and fails with [`TargetGone`](/docs/api/browser/Target#TargetGone) if the page crashes.
- A consumer more than 1,000 events behind fails the stream with
  [`EventOverflow`](/docs/api/browser/Subscription#EventOverflow). Nothing is dropped silently.

## History

`history` reads what already happened, such as what threw or what the page logged:

```ts
import { Page, UncaughtException } from "@usestrider/browser"
import { Effect } from "effect"

const pageErrors = Effect.fn("pageErrors")(function*(page: Page.Page) {
  const thrown = yield* UncaughtException.history(page)
  if (thrown.dropped > 0) {
    yield* Effect.logWarning(`${thrown.dropped} older errors were dropped`)
  }
  return thrown.entries.map((error) => error.message)
})
```

- The log keeps the latest 100 events of each kind per page, or the context's
  [`eventLog`](/docs/pages/contexts#settings-for-the-whole-session). `dropped` counts the
  rest.
- To catch what an action causes, use `next`. There's no "last event" to read.

## Deadlines for waits

Without one, a wait gets the 30-second default, counted from `next`, which a large export can outlast. Set a longer
one on `next`:

```ts
import { Deadline, Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const bigExport = Effect.fn("bigExport")(function*(page: Page.Page) {
  const archive = yield* Download.next(page).pipe(Deadline.within("2 minutes"))
  yield* page.getByRole("button", { name: "Export everything" }).click()
  const file = yield* archive
  yield* file.finished.pipe(Deadline.within("10 minutes"))
})
```

Steps between `next` and the wait count against it. A wait ends with its event, `TargetGone` when the page closes,
or [`Timeout`](/docs/deadlines#timeouts).
