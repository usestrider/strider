An event is something the browser reports about a page as it happens, such as a popup, a download, or a console
message. Each kind has a module that waits for the next one, streams them, or reads the ones already logged.

## Subscribing before acting

A download or a popup can arrive before the action that caused it returns. `Download.next` subscribes when it's
called and gives a wait, an `Effect` of the first matching download, so call it before the action:

```ts
import { Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const exportCsv = Effect.fn("exportCsv")(function*(page: Page.Page) {
  const download = yield* Download.next(page) // subscribed from here on
  yield* page.getByRole("button", { name: "Export CSV" }).click()
  const file = yield* download // the first download since
  yield* file.saveAs("./export.csv")
})
```

Subscribing after the click is a race. If the download came first, the wait times out with a hint: "a download
came 12 ms before Download.next subscribed; call Download.next before the action that causes it".

## Next, stream, and history

Use `next` for the one event an action causes, `stream` to watch every event for a while, such as console errors,
and `history` to read what happened before you looked.
Dialogs and file choosers also have [`handle`](/docs/events/kinds#dialogs-and-file-choosers):

| Verb      | Does                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| `next`    | subscribes now; its value is a wait for the first match                                       |
| `stream`  | subscribes now; gives a `Stream` of every match from then on                                  |
| `history` | reads the matches already logged, and never waits                                             |
| `handle`  | dialogs and file choosers: registers a function that decides each one until its scope closes  |

A filter is data, applied before events are buffered, so the events it rejects never count toward the
[events a stream buffers](#streams) for a slow consumer. `where`, after the filter, adds a predicate for
anything a filter can't say: it gets the event and returns an `Effect` of a boolean:

```ts
import { Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const downloadInvoice = Effect.fn("downloadInvoice")(function*(page: Page.Page) {
  const invoice = yield* Download.next(
    page,
    { url: "**/invoices/**" },
    (download) => Effect.succeed(download.suggestedFilename.endsWith(".pdf"))
  )
  yield* page.getByRole("link", { name: "Download invoice" }).click()
  const file = yield* invoice
  yield* file.saveAs(`./invoices/${file.suggestedFilename}`)
})
```

## Event modules

Each module has the verbs above, and filters on fields of its own:

| Module              | Reports                                                     | Filter                             |
| ------------------- | ----------------------------------------------------------- | ---------------------------------- |
| [`PageNavigation`](/docs/events/kinds#navigations) | navigations of the page, and optionally its frames           | `url`, `frames`, and `waitUntil` for `next` |
| [`Popup`](/docs/events/kinds#popups) | pages this page opened                                       | `url`                              |
| [`Dialog`](/docs/events/kinds#dialogs-and-file-choosers) | alerts, confirms, prompts, and `beforeunload`                | `kind`                             |
| [`FileChooser`](/docs/events/kinds#dialogs-and-file-choosers) | file pickers the page opened                                 | `multiple`                         |
| [`Download`](/docs/events/kinds#downloads) | downloads                                                    | `url`                              |
| [`NetworkRequest`](/docs/events/network) | requests, one per redirect hop                               | `url`, `method`, `resourceType`    |
| [`NetworkResponse`](/docs/events/network) | responses, with their bodies when asked                      | `url`, `method`, `status`, `body`  |
| `ConsoleMessage`    | console output                                               | `level`, `text`                    |
| `UncaughtException` | errors nothing caught, and rejections nothing handled        | `message`                          |
| [`BrowserWorker`](/docs/api/browser/BrowserWorker) | workers the page or context started                          | `url`, `kind`                      |
| [`NetworkConnection`](/docs/api/browser/NetworkConnection) | WebSockets and event sources, with their frames               | `url`, `kind`                      |
| [`AutoResolution`](/docs/api/browser/AutoResolution) | dialogs, choosers, and requests decided by a default         | `subject`                          |

## Several outcomes

One action can cause several events, such as a navigation and the response that placed the order. Subscribe to
each before the action, then collect them together:

```ts
import { NetworkResponse, Page, PageNavigation } from "@usestrider/browser"
import { Effect } from "effect"

const pay = Effect.fn("pay")(function*(page: Page.Page) {
  const confirmation = yield* PageNavigation.next(page, { url: "**/orders/*" })
  const order = yield* NetworkResponse.next(page, { url: "**/api/order" })
  yield* page.getByRole("button", { name: "Pay" }).click()
  const [navigation, placed] = yield* Effect.all([confirmation, order])
  return { url: navigation.url, status: placed.status }
})
```

A wait keeps its event from when it arrived. Running it again gives the same event.

## Streams

`stream` gives every match from when it subscribes. Fork its consumer into the scope to watch in the background:

```ts
import { ConsoleMessage, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const logErrors = Effect.fn("logErrors")(function*(page: Page.Page) {
  const errors = yield* ConsoleMessage.stream(page, { level: "error" })
  yield* errors.pipe(
    Stream.runForEach((message) => Console.error(`[page] ${message.text}`)),
    Effect.forkScoped
  )
})
```

- A stream ends when its page or context closes, and fails with
  [`TargetGone`](/docs/api/browser/Target#TargetGone) when it ends any other way, such as a crash or a lost
  connection.
- A consumer more than 1,000 events behind fails the stream with
  [`EventOverflow`](/docs/api/browser/Subscription#EventOverflow). Nothing is dropped silently.
  [`Subscription.withCapacity`](/docs/api/browser/Subscription#withCapacity) sets another bound for the streams
  that subscribe inside it.

## History

`history` reads what already happened, such as what threw or what the page logged:

```ts
import { Page, UncaughtException } from "@usestrider/browser"
import { Effect } from "effect"

const pageErrors = Effect.fn("pageErrors")(function*(page: Page.Page) {
  const thrown = yield* UncaughtException.history(page)
  if (thrown.dropped > 0) {
    yield* Effect.logWarning(`${thrown.dropped} older errors were dropped`)
  }
  return thrown.entries.map((error) => error.message)
})
```

- The log keeps the latest 100 events of each kind per page, or the context's
  [`eventLog`](/docs/pages/contexts#settings-for-a-contexts-life). `dropped` counts the
  rest.
- To catch what an action causes, use `next`. There's no "last event" to read.

## Deadlines for waits

A wait's deadline counts from `next`, so set one there for a wait that can outlast the default, such as a large
export:

```ts
import { Deadline, Download, Page } from "@usestrider/browser"
import { Effect } from "effect"

const bigExport = Effect.fn("bigExport")(function*(page: Page.Page) {
  const archive = yield* Download.next(page).pipe(Deadline.within("2 minutes"))
  yield* page.getByRole("button", { name: "Export everything" }).click()
  const file = yield* archive
  yield* file.finished.pipe(Deadline.within("10 minutes"))
})
```

Steps between `next` and the wait count against it. A wait ends with its event, `TargetGone` when the page closes,
or [`Timeout`](/docs/deadlines#timeouts).
