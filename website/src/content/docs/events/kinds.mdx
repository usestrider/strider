A navigation can end on an error page, a popup is a page to act on, a dialog blocks its page until something
decides it, and a download's file isn't whole when its event comes. Their modules add what each needs to the
[`next`, `stream` and `history`](/docs/events/events#next-stream-and-history) every event module has.

## Navigations

[`Expect.toHaveURL`](/docs/pages/expectations#the-matchers) says where the page is, not what got it there.
`PageNavigation.next` gives the navigation the action caused, with its response, so an error page or a
same-document change can be told apart:

```ts
import { Page, PageNavigation } from "@usestrider/browser"
import { Effect, Option } from "effect"

const openOrders = Effect.fn("openOrders")(function*(page: Page.Page) {
  const orders = yield* PageNavigation.next(page, {
    url: "**/orders",
    waitUntil: "load"
  })
  yield* page.getByRole("link", { name: "Orders" }).click()
  const navigation = yield* orders
  if (navigation._tag !== "Committed") return Option.none()
  return Option.map(navigation.response, (response) => response.status)
})
```

The navigation is data: `Committed` with its response, `SameDocument` for a fragment or the History API, which
WebKit doesn't report, `Restored` from the back/forward cache, and the rest of
[`PageNavigation`'s variants](/docs/api/browser/PageNavigation#PageNavigation). `waitUntil: "load"` also waits for
the document to load.

## Popups

`Popup.next` gives a page the page opened, as a `Page` that closes with its opener's scope:

```ts
import { Dialog, Page, Popup } from "@usestrider/browser"
import { Effect } from "effect"

const connectAccount = Effect.fn("connectAccount")(function*(page: Page.Page) {
  const popups = yield* Popup.next(page)
  yield* page.getByText("Connect account").click()
  const popup = yield* popups
  yield* Dialog.handle(popup, Dialog.acceptAll)
  yield* popup.getByRole("button", { name: "Allow" }).click()
})
```

Here [`Dialog.handle`](#dialogs-and-file-choosers) accepts every dialog the popup opens. The popup is reported
before its first document loads, so a handler or route registered on it applies to that document; a Chromium you
attached to doesn't hold a popup back, so there its first document may load before either.

On Chromium, a popup's opener stops rendering, and actions on it time out with a hint saying so. Call
[`page.activate`](/docs/api/browser/Page#Page.activate) on the opener first, or make the context with
[`focus: "emulated"`](/docs/tools/testing#concurrent-pages). Firefox and WebKit keep rendering it, but WebKit
names no opener, so `Popup.next` fails there with `Unsupported`:
[wait for the context's new page](/docs/browsers/webkit#differences) instead.

## Dialogs and file choosers

A dialog blocks its page until it's decided, and the action that opened it doesn't return until then, so a wait
collected after the action would come too late. Register a handler before it opens; the handler lasts until its
scope closes:

```ts
import { Dialog, Page } from "@usestrider/browser"
import { Effect } from "effect"

const deleteAccount = Effect.fn("deleteAccount")(function*(page: Page.Page) {
  yield* Dialog.handle(page, (dialog) => {
    switch (dialog._tag) {
      case "Confirm": {
        const yes = dialog.message.includes("delete")
        return yes ? dialog.accept : dialog.dismiss
      }
      case "Prompt":
        return dialog.respond("DELETE")
      case "Alert":
        return dialog.accept
      case "BeforeUnload":
        return dialog.leave
      case "Unknown":
        return dialog.accept
    }
  })
  yield* page.getByRole("button", { name: "Delete account" }).click()
})
```

- Each decision is an Effect: return it directly, or end a generator with `return yield* dialog.accept`
  after other work.
- Each kind offers only its own decisions: an alert can only be accepted, a prompt can be answered.
- `Dialog.acceptAll` and [`Dialog.dismissAll`](/docs/api/browser/Dialog#dismissAll) are ready-made handlers.
- On WebKit every dialog is `Unknown`, since WebKit doesn't say which kind is open: a handler meant for WebKit
  [decides from the message](/docs/browsers/webkit#differences) in its `Unknown` branch.

A dialog no handler decides goes to the context's
[`dialogs` policy](/docs/pages/contexts#settings-for-a-contexts-life), `"dismiss"` by default, at once. Under
`"dismiss"`, a `beforeunload` dialog still leaves the page, so closing it never hangs. Each decision a default
made is an `AutoResolution` event, so a flow can report the dialogs nothing handled:

```ts
import { AutoResolution, Page } from "@usestrider/browser"
import { Effect } from "effect"

const undecidedDialogs = Effect.fn("undecidedDialogs")(function*(page: Page.Page) {
  const decided = yield* AutoResolution.history(page, { subject: "Dialog" })
  for (const { subject, decision } of decided.entries) {
    if (subject._tag === "Dialog") {
      yield* Effect.logWarning(`${subject.kind} "${subject.message}": ${decision}`)
    }
  }
})
```

File choosers work the same way: register a handler with `FileChooser.handle` before the click that opens one:

```ts
import { FileChooser, FileInput, Page } from "@usestrider/browser"
import { Effect } from "effect"

const uploadPhoto = Effect.fn("uploadPhoto")(function*(page: Page.Page) {
  yield* FileChooser.handle(page, FileChooser.choose(FileInput.local("./photo.jpg")))
  yield* page.getByRole("button", { name: "Upload photo" }).click()
})
```

A chooser no handler answers is canceled, and reported as an `AutoResolution` too. On WebKit,
`FileChooser.handle` fails with `Unsupported`, and the browser cancels each chooser itself.

## Downloads

A download's event comes when it starts, before its file is complete. The handle, with its file, status and
suggested name, follows it to the end, so you save or read the file once it's whole:

```ts
import { Download, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const exportReport = Effect.fn("exportReport")(function*(page: Page.Page) {
  const pdf = yield* Download.next(page)
  yield* page.getByText("Export PDF").click()
  const report = yield* pdf
  yield* report.status.changes.pipe(
    Stream.runForEach((status) => Console.log(status._tag)),
    Effect.forkScoped
  )
  yield* report.saveAs(`./reports/${report.suggestedFilename}`)
})

const exportedHeader = Effect.fn("exportedHeader")(function*(page: Page.Page) {
  const csv = yield* Download.next(page)
  yield* page.getByRole("button", { name: "Export CSV" }).click()
  const text = yield* (yield* csv).stream.pipe(Stream.decodeText(), Stream.mkString)
  return text.split("\n")[0]
})
```

- The file is kept in the context's [`downloads`](/docs/pages/contexts#settings-for-a-contexts-life) directory.
  The default, a temporary directory, is removed with the context; a `{ directory }` of yours never is.
- `saveAs` copies it out once complete; `stream` gives its bytes; `finished` waits for it to end.
- WebKit reports no downloads: `Download.next` fails there with `Unsupported`.
