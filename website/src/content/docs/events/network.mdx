## Requests and responses are events

What a page sends and receives is reported through two event modules, `NetworkRequest` and `NetworkResponse`,
with the same `next`, `stream` and `history` as every other event. A request is reported when it's sent and a response when it arrives, one of
each per redirect hop. Both are Schemas, and use Effect's HTTP types: headers are Effect's `Headers`, methods its
`HttpMethod`.

Waiting for a response follows the rule for every event, subscribe and then act:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const saveSettings = Effect.fn("saveSettings")(function*(page: Page.Page) {
  const saved = yield* NetworkResponse.next(page, { url: "**/settings", method: "PUT" })
  yield* page.getByRole("button", { name: "Save" }).click()
  const response = yield* saved
  return response.status
})
```

`next` for requests and responses needs a `url`, a glob such as `"**/api/**"`, a URL, or a `URLPattern`. A filter
can also name a `method`, and for responses a `status` or a predicate over it, such as `(status) => status >= 400`.

## Bodies, decoded

A response's body is collected only when a subscription asks for it, with `body`: any decoder of an Effect
`HttpIncomingMessage`, such as `HttpIncomingMessage.schemaBodyJson` and a Schema. The response arrives with the
body decoded, and `where` is typed by it:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"
import { HttpIncomingMessage } from "effect/http"

const Item = Schema.Struct({ id: Schema.String, quantity: Schema.Number })
const Cart = Schema.Struct({ items: Schema.Array(Item) })
const cartBody = HttpIncomingMessage.schemaBodyJson(Cart)

const addToCart = Effect.fn("addToCart")(function*(page: Page.Page) {
  const added = yield* NetworkResponse.next(
    page,
    { url: "**/api/cart", method: "POST", body: cartBody },
    (response) => Effect.succeed(response.body.items.length > 0)
  )
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  const response = yield* added
  return response.body.items
})
```

The body is copied out of the browser, so it outlives the subscription and even the page. Bodies are collected up
to 10 MiB unless `NetworkResponse.withBodyLimit` says otherwise. A response with no body to give fails the wait
with `BodyUnavailable`, which says why: a redirect, a body over the limit, one the browser already let go of, a
transfer that failed, or a stream that never ends, such as server-sent events. A body that isn't what it was
decoded as fails with `MalformedBody`.

Reading a body needs read access to the page, which a page you opened always has.

## Watching all of it

`stream` gives every match from now on. Here every `fetch` the page makes is logged, in the background, until the
scope closes:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const logFetches = Effect.fn("logFetches")(function*(page: Page.Page) {
  const requests = yield* NetworkRequest.stream(page, { resourceType: "fetch" })
  yield* requests.pipe(
    Stream.runForEach((request) => Console.log(request.method, request.url)),
    Effect.forkScoped
  )
})
```

A context's requests and responses can be watched the same way, by passing the context: every page in it, and its
shared and service workers.

## What already happened

`history` reads the requests or responses already logged, without bodies:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const failedCalls = Effect.fn("failedCalls")(function*(page: Page.Page) {
  const failed = yield* NetworkResponse.history(page, {
    url: "**/api/**",
    status: (status) => status >= 400
  })
  return failed.entries.map((response) => `${response.status} ${response.url}`)
})
```

## Who answered

A response says what answered it in `servedBy`: `network`, `cache`, `serviceWorker`, `route` when one of your
routes fulfilled it, or `cacheOrServiceWorker` where Firefox can't tell the two apart.

## The headers as sent

A request event's headers are what the browser reported when it sent the request, and Chromium and WebKit leave
out some that the network stack adds, `Cookie` among them. `NetworkRequest.headersSent` waits until the headers as
actually sent are known:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Effect } from "effect"
import { Headers } from "effect/http"

const sentCookies = Effect.fn("sentCookies")(function*(page: Page.Page) {
  const call = yield* NetworkRequest.next(page, { url: "**/api/profile" })
  yield* page.getByRole("link", { name: "Profile" }).click()
  const request = yield* call
  const headers = yield* NetworkRequest.headersSent(page, request)
  return Headers.get(headers, "cookie")
})
```

Header values that carry credentials, such as cookies and authorization, are treated as secret, and redacted
wherever they're shown: in logs, errors and spans.

## Sending it yourself

There is no `fetch` on a captured request, because a request sent from outside the browser wouldn't have the
browser's cookies, cache, proxy or service workers. When that is what you want, say so:
`NetworkRequest.toHttpClientRequest(request)` turns it into Effect's `HttpClientRequest`, for your own
`HttpClient` to send. To change what the browser sends or receives, use a route, on the next page.
