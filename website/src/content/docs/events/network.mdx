A page's requests and responses are events, reported as each is sent and arrives. Wait on the response an action
causes to check what the server said, and decode its body with a Schema to get typed data.

## Request and response events

`NetworkRequest` and `NetworkResponse` are event modules, with `next`, `stream`, and `history`.

- Each redirect hop has its own request and response.
- Both are Schemas, with Effect's `Headers` and `HttpMethod`.
- [`NetworkRequest.failure`](/docs/events/request-failures) reads why a request's transfer failed.

`next` needs a `url`: a glob such as `"**/api/**"`, a URL, or a `URLPattern` string with `:name` groups, such as
`"https://shop.example.com/api/orders/:id"`. A filter can also name a `method`; a request filter a `resourceType`,
such as `"fetch"`; and a response filter a `status`, or a predicate, such as `(status) => status >= 400`:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const deleteOrder = Effect.fn("deleteOrder")(function*(page: Page.Page) {
  const deleted = yield* NetworkResponse.next(page, {
    url: "https://shop.example.com/api/orders/:id",
    method: "DELETE",
    status: 204
  })
  yield* page.getByRole("button", { name: "Delete order" }).click()
  yield* deleted
})
```

For a request you already observed, [retain its response association](/docs/events/request-responses) to wait for
that exact hop rather than matching by URL.

## Decoding bodies

A body is collected only when a subscription asks with `body`: a decoder of an Effect `HttpIncomingMessage`, such
as `HttpIncomingMessage.schemaBodyJson`, which fails if the body isn't the Schema's shape. The response arrives
decoded, and `where`, the [predicate](/docs/events/events#next-stream-and-history) after the filter, gets it typed:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"
import { HttpIncomingMessage } from "effect/http"

const Item = Schema.Struct({ id: Schema.String, quantity: Schema.Number })
const Cart = Schema.Struct({ items: Schema.Array(Item) })
const cartBody = HttpIncomingMessage.schemaBodyJson(Cart)

const addToCart = Effect.fn("addToCart")(function*(page: Page.Page) {
  const added = yield* NetworkResponse.next(
    page,
    { url: "**/api/cart", method: "POST", body: cartBody },
    (response) => Effect.succeed(response.body.items.length > 0)
  )
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  const response = yield* added
  return response.body.items
})
```

- The body is copied out of the browser, so it outlives the page.
- Collection ends with the subscription's scope or when borrowed inspect access is released; a subscription started with an expired grant fails with `TargetGone`.
- A body that can't be read fails the wait with a `ResponseError`, whose reason is one of:
  - `BodyUnavailable`: there's no body to read. Its `why` says which: a redirect, over the limit, released by the
    browser, a failed transfer, or a stream that never ends, such as server-sent events.
  - `MalformedBody`: the body isn't what it was read as.
  - `Unsupported`: the browser cannot supply this body's bytes. On Firefox, a terminal response with status 301,
    302, 303, 307, or 308 without a `Location` header fails immediately with capability
    `"network.responseBody.terminalRedirect"`, because Firefox does not answer `network.getData` for it. Other
    statuses remain readable, and Chromium and WebKit return these bodies normally. Followed redirect hops
    still fail with `BodyUnavailable`, `why: "redirect"`; their final response's body can be collected.
- Reading a body needs [read access](/docs/pages/attaching#access-levels) to the page.

Bodies are collected up to 10 MiB; `NetworkResponse.withBodyLimit` raises it for the subscriptions inside it. A step
that can do without the body catches its reason:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect, Option } from "effect"

const exportOrders = Effect.fn("exportOrders")(function*(page: Page.Page) {
  const exported = yield* NetworkResponse.next(page, {
    url: "https://shop.example.com/api/orders/export",
    body: (message) => message.arrayBuffer
  }).pipe(NetworkResponse.withBodyLimit("50 MiB"))
  yield* page.getByRole("button", { name: "Export orders" }).click()
  return yield* exported.pipe(
    Effect.map((response) => Option.some(response.body)),
    Effect.catchReason(
      "ResponseError",
      "BodyUnavailable",
      (unavailable) =>
        Effect.logWarning(`No export: ${unavailable.why}`).pipe(
          Effect.as(Option.none())
        )
    )
  )
})
```

A request can also be captured with a decoder; see [Request bodies](/docs/events/request-bodies) for submitted
text, JSON, forms, byte limits, and browser restrictions.

## Streams and history

`stream` gives every match from now on. Given a context rather than a page, it watches every page in it, and on
Chromium its shared and service workers too. This logs each `fetch` in the context until the scope closes:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const logFetches = Effect.fn("logFetches")(function*(page: Page.Page) {
  const requests = yield* NetworkRequest.stream(page.context, { resourceType: "fetch" })
  yield* requests.pipe(
    Stream.runForEach((request) => Console.log(request.method, request.url)),
    Effect.forkScoped
  )
})
```

`history` reads the requests or responses already logged, without bodies:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const failedCalls = Effect.fn("failedCalls")(function*(page: Page.Page) {
  const failed = yield* NetworkResponse.history(page, {
    url: "**/api/**",
    status: (status) => status >= 400
  })
  return failed.entries.map((response) => `${response.status} ${response.url}`)
})
```

## Response sources

A response's `servedBy` says what answered it, such as a cache or a service worker rather than the server, so you
can check caching or offline support. It's `"network"`, `"cache"`, `"serviceWorker"`, `"route"` when a
[route](/docs/events/routes) fulfilled it, `"cacheOrServiceWorker"` on Firefox, which can't tell them apart, or
`"unknown"`, which WebKit can report when it doesn't know:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const shellWorksOffline = Effect.fn("shellWorksOffline")(function*(page: Page.Page) {
  return yield* Effect.scoped(Effect.gen(function*() {
    yield* page.emulate({ network: "offline" })
    const shell = yield* NetworkResponse.next(page, { url: "**/app.js" })
    yield* page.reload()
    const { servedBy } = yield* shell
    return servedBy === "serviceWorker" || servedBy === "cacheOrServiceWorker"
  }))
})
```

## Sent headers

A request event's headers are what the browser reported on sending. Chromium and WebKit leave out some the network
stack adds, such as `Cookie`. `NetworkRequest.headersSent` waits for the headers as sent (WebKit's still lack
`Cookie`). Where [`listFor`](/docs/pages/contexts#cookies-and-storage) gives the cookies a request to a URL would
send, `headersSent` gives what this request did send, every header and not only cookies:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Effect } from "effect"
import { Headers } from "effect/http"

const sentCookies = Effect.fn("sentCookies")(function*(page: Page.Page) {
  const call = yield* NetworkRequest.next(page, { url: "**/api/profile" })
  yield* page.getByRole("link", { name: "Profile" }).click()
  const request = yield* call
  const headers = yield* NetworkRequest.headersSent(page, request)
  return {
    cookie: Headers.get(headers, "cookie"),
    language: Headers.get(headers, "accept-language")
  }
})
```

The operation's deadline bounds the wait. If the request ends, is evicted from the retained 1000 hops, or loses
its frame, worker, context, page, or browser connection, the wait returns already-attributed sent headers, or the
immutable request event's headers when none were reported. A new lookup after eviction returns that snapshot too.
These fallbacks can omit network additions such as `Cookie`.

Inside a request-phase [route handler](/docs/events/routes), awaiting sent headers before continuing the request
prevents it from being sent. Continue the route first and inspect sent headers outside the handler, as in the
event subscription example above. On Chromium, the same trap applies while holding the response: attribution
can need the response or redirect information. Read `request.headers` for an immediate snapshot inside a handler.

Credential headers, such as cookies and authorization, are redacted in logs, errors, and spans.

## Resending requests

`NetworkRequest.toHttpClientRequest` turns a captured request into an Effect `HttpClientRequest` with its method,
URL, and headers, to send again as it is or changed. It keeps what the page put in, such as an auth header, which
stays redacted in logs. It has no body, so a replay of a
`POST` sets one. Sent from outside the browser, it goes without the browser's cache, proxy, and service workers, and
without its cookies, except on Firefox, whose request events carry the `Cookie` the browser sent:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"
import { HttpClient, HttpClientRequest, HttpIncomingMessage } from "effect/http"

const Orders = Schema.Struct({ orders: Schema.Array(Schema.String) })

const nextPageOfOrders = Effect.fn("nextPageOfOrders")(function*(page: Page.Page) {
  const call = yield* NetworkRequest.next(page, { url: "**/api/orders**" })
  yield* page.getByRole("link", { name: "Orders" }).click()
  const firstPage = NetworkRequest.toHttpClientRequest(yield* call)
  const response = yield* HttpClient.execute(
    HttpClientRequest.setUrlParam(firstPage, "page", "2")
  )
  const { orders } = yield* HttpIncomingMessage.schemaBodyJson(Orders)(response)
  return orders
})
```

To change what the browser sends or receives, use a [route](/docs/events/routes).

Read a request's predecessor or successor with [scoped redirect access](/docs/events/redirects).

For native phase measurements, opt into [request timings](/docs/events/request-timings) when creating the context.

For native byte accounting, opt into [request sizes](/docs/events/request-sizes) when creating the context.
