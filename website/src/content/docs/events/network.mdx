## Requests and responses are events

`NetworkRequest` and `NetworkResponse` are event modules, with `next`, `stream` and `history`.

- A request is reported when sent and a response when it arrives, one of each per redirect hop.
- Both are Schemas, with Effect's `Headers` and `HttpMethod`.

Subscribe, then act:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const saveSettings = Effect.fn("saveSettings")(function*(page: Page.Page) {
  const saved = yield* NetworkResponse.next(page, { url: "**/settings", method: "PUT" })
  yield* page.getByRole("button", { name: "Save" }).click()
  const response = yield* saved
  return response.status
})
```

`next` needs a `url`: a glob such as `"**/api/**"`, a URL, or a `URLPattern`. A filter can also name a `method`,
and for responses a `status` or a predicate, such as `(status) => status >= 400`.

## Bodies, decoded

A body is collected only when a subscription asks with `body`: a decoder of an Effect `HttpIncomingMessage`, such
as `HttpIncomingMessage.schemaBodyJson`. The response arrives decoded, and `where` is typed by it:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"
import { HttpIncomingMessage } from "effect/http"

const Item = Schema.Struct({ id: Schema.String, quantity: Schema.Number })
const Cart = Schema.Struct({ items: Schema.Array(Item) })
const cartBody = HttpIncomingMessage.schemaBodyJson(Cart)

const addToCart = Effect.fn("addToCart")(function*(page: Page.Page) {
  const added = yield* NetworkResponse.next(
    page,
    { url: "**/api/cart", method: "POST", body: cartBody },
    (response) => Effect.succeed(response.body.items.length > 0)
  )
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  const response = yield* added
  return response.body.items
})
```

- The body is copied out of the browser, so it outlives the page.
- Bodies are collected up to 10 MiB; `NetworkResponse.withBodyLimit` changes it.
- No body fails the wait with `BodyUnavailable`, saying why: a redirect, over the limit, already let go, a failed
  transfer, or a stream that never ends, such as server-sent events.
- A body that doesn't decode fails with `MalformedBody`.
- Reading a body needs read access to the page.

## Watching all of it

`stream` gives every match from now on. This logs each `fetch` until the scope closes:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Console, Effect, Stream } from "effect"

const logFetches = Effect.fn("logFetches")(function*(page: Page.Page) {
  const requests = yield* NetworkRequest.stream(page, { resourceType: "fetch" })
  yield* requests.pipe(
    Stream.runForEach((request) => Console.log(request.method, request.url)),
    Effect.forkScoped
  )
})
```

Pass a context instead of a page to watch every page in it, and its shared and service workers.

## What already happened

`history` reads the requests or responses already logged, without bodies:

```ts
import { NetworkResponse, Page } from "@usestrider/browser"
import { Effect } from "effect"

const failedCalls = Effect.fn("failedCalls")(function*(page: Page.Page) {
  const failed = yield* NetworkResponse.history(page, {
    url: "**/api/**",
    status: (status) => status >= 400
  })
  return failed.entries.map((response) => `${response.status} ${response.url}`)
})
```

## Who answered

`servedBy` is `network`, `cache`, `serviceWorker`, `route` when a route fulfilled it, or `cacheOrServiceWorker` on
Firefox, which can't tell them apart.

## The headers as sent

A request event's headers are what the browser reported on sending. Chromium and WebKit leave out some the network
stack adds, such as `Cookie`. `NetworkRequest.headersSent` waits for the headers as sent (WebKit's still lack
`Cookie`):

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Effect } from "effect"
import { Headers } from "effect/http"

const sentCookies = Effect.fn("sentCookies")(function*(page: Page.Page) {
  const call = yield* NetworkRequest.next(page, { url: "**/api/profile" })
  yield* page.getByRole("link", { name: "Profile" }).click()
  const request = yield* call
  const headers = yield* NetworkRequest.headersSent(page, request)
  return Headers.get(headers, "cookie")
})
```

Credential headers, such as cookies and authorization, are redacted in logs, errors and spans.

## Sending it yourself

A captured request has no `fetch`: sent from outside, it wouldn't have the browser's cookies, cache, proxy or
service workers. `NetworkRequest.toHttpClientRequest` turns it into an Effect `HttpClientRequest` for your own
`HttpClient`:

```ts
import { NetworkRequest, Page } from "@usestrider/browser"
import { Effect } from "effect"
import { HttpClient } from "effect/http"

const replay = Effect.fn("replay")(function*(page: Page.Page) {
  const call = yield* NetworkRequest.next(page, { url: "**/api/report" })
  yield* page.getByRole("button", { name: "Refresh" }).click()
  const request = NetworkRequest.toHttpClientRequest(yield* call)
  return yield* HttpClient.execute(request)
})
```

To change what the browser sends or receives, use a [route](/docs/events/routes).
