Launching a browser for each test is slow, and tests whose pages share cookies and storage leak state into each
other. Under Vitest, each test is an Effect program on one browser per file, with a fresh context for each page, so
the steps you wrote for scripts run in tests unchanged.

## Writing a test

Tests run under Vitest with Effect's `@effect/vitest`, and `@usestrider/vitest` connects the two:

```sh
pnpm add -D vitest @effect/vitest @usestrider/vitest
```

A test opens its page as a script does, with `Browser.newPage()`. `VitestBrowser.layer` provides the backend you
give it, unchanged, plus `TestRun`, the running test, which [attaching files](#attaching-files) needs:

```ts title="checkout.test.ts"
import { NodeServices } from "@effect/platform-node"
import { layer } from "@effect/vitest"
import { Browser, Expect, Page } from "@usestrider/browser"
import { Chromium } from "@usestrider/browser/chromium"
import { VitestBrowser } from "@usestrider/vitest"
import { Config, Effect, Layer } from "effect"

// A step, as a script would write it
const addToCart = Effect.fn("addToCart")(function*(page: Page.Page) {
  yield* page.goto("https://shop.example.com")
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  yield* page.getByText("1 item").pipe(Expect.toBeVisible)
})

const ChromiumLive = Chromium.layerConfig({
  executablePath: Config.String("CHROMIUM_PATH")
}).pipe(Layer.provide(NodeServices.layer))

const BrowserLive = VitestBrowser.layer(ChromiumLive)

layer(BrowserLive, { excludeTestServices: true })("checkout", (it) => {
  it.effect("adds a product to the cart", () =>
    Effect.gen(function*() {
      const page = yield* Browser.newPage()
      yield* addToCart(page)
    }))

  it.effect("empties the cart", () =>
    Effect.gen(function*() {
      const page = yield* Browser.newPage()
      yield* addToCart(page)
      yield* page.getByRole("button", { name: "Empty cart" }).click()
      yield* page.getByText("Your cart is empty").pipe(Expect.toBeVisible)
    }))
})
```

- `layer` builds the layer once per block: the file's tests share one browser. Each `Browser.newPage()` makes a
  fresh context, closed when the test ends.
- Files run in parallel, each with its own browser.
- `excludeTestServices: true` runs tests on the real clock. Without it, an `Effect.sleep` of yours waits on a
  `TestClock` nobody moves. Strider's deadlines use the real clock either way.
- A failed expectation fails the test with [`ExpectationFailed`](/docs/errors#failed-expectations): what was
  expected, seen and nearest.
- A step that takes a page, such as `addToCart`, runs the same in a test and a script. To sign in once per file,
  start each test's page from [saved storage state](/docs/pages/contexts#logging-in-once).

Vitest's default `testTimeout` is five seconds for the whole test, shorter than Strider's thirty-second budget
per operation, so a slow step can end with Vitest's generic timeout before Strider reports its failure.
Raise `testTimeout` in your Vitest config to allow time for all the test's operations:

```ts title="vitest.config.ts"
import { defineConfig } from "vitest/config"

export default defineConfig({
  test: { testTimeout: 60_000 }
})
```

## Concurrent pages

A browser throttles the timers and rendering of pages in the background and gives focus to one page only, so
with several pages at once, a background page's actions can time out and `toBeFocused` fails on all but one. Use
these when a file's tests run concurrently, or a test drives several pages:

```ts title="dashboards.test.ts"
import { NodeServices } from "@effect/platform-node"
import { layer } from "@effect/vitest"
import { Browser, Expect, LaunchProfile } from "@usestrider/browser"
import { Chromium } from "@usestrider/browser/chromium"
import { VitestBrowser } from "@usestrider/vitest"
import { Effect, Layer } from "effect"

const ChromiumLive = Chromium.layer({
  executablePath: "/usr/bin/chromium",
  profile: LaunchProfile.concurrent
}).pipe(Layer.provide(NodeServices.layer))

const BrowserLive = VitestBrowser.layer(ChromiumLive)

layer(BrowserLive, { concurrent: true, excludeTestServices: true })(
  "dashboards",
  (it) => {
    it.effect("focuses the sales search", () =>
      Effect.gen(function*() {
        const page = yield* Browser.newPage({ focus: "emulated" })
        yield* page.goto("https://app.example.com/sales")
        yield* page.getByRole("searchbox").pipe(Expect.toBeFocused)
      }))

    it.effect("focuses the stock search", () =>
      Effect.gen(function*() {
        const page = yield* Browser.newPage({ focus: "emulated" })
        yield* page.goto("https://app.example.com/stock")
        yield* page.getByRole("searchbox").pipe(Expect.toBeFocused)
      }))
  }
)
```

- `LaunchProfile.concurrent` turns off throttling of background timers and renderers.
- `focus: "emulated"` makes every page behave as if focused.
- `concurrent: true` runs the file's tests at once, on its one browser.
- Pages can tell both apart from a normal browser, so neither is a default.

For automatic recording and attachment on failure, see [Traces for failed tests](/docs/tools/test-traces).

## Attaching files

A trace written to disk isn't tied to the test that made it, so finding a failed test's trace means matching file
names by hand. `TestRun`, which `VitestBrowser.layer` provides, attaches a file to the running test as a Vitest
artifact, kept with its result: `run.attach` takes the file's kind, `"Trace"`, `"Har"` or `"Screenshot"`, and its
path, such as a [trace](/docs/tools/recordings#traces)'s. Bind the callback with
`VitestBrowser.withTest(context)` to capture its identity, retry attempt and attachment owner, even with a shared
browser layer, or with a per-effect browser layer in either composition order. Call it again for each retry.
Complete attachments before the callback ends: Vitest does not guarantee that later artifacts reach reporters. Without this binding the adapter uses Vitest's global current-test
lookup, which supports sequential tests only and can select another callback during concurrent tests:

```ts title="cart.test.ts"
import { NodeServices } from "@effect/platform-node"
import { layer } from "@effect/vitest"
import { Browser, Expect, Trace } from "@usestrider/browser"
import { Chromium } from "@usestrider/browser/chromium"
import { TestRun } from "@usestrider/browser/test"
import { VitestBrowser } from "@usestrider/vitest"
import { Config, Effect, Layer } from "effect"

const ChromiumLive = Chromium.layerConfig({
  executablePath: Config.String("CHROMIUM_PATH")
}).pipe(Layer.provide(NodeServices.layer))

layer(VitestBrowser.layer(ChromiumLive), { excludeTestServices: true })(
  "cart",
  (it) => {
    it.effect("adds a product to the cart", (context) =>
      Effect.gen(function*() {
        const page = yield* Browser.newPage()
        const trace = yield* Trace.record(page, { screenshots: "perAction" })
        const run = yield* TestRun.TestRun
        const attachTrace = trace.exportTrace("traces/add-to-cart.zip").pipe(
          Effect.flatMap((path) => run.attach({ _tag: "Trace", path })),
          Effect.ignore
        )
        // Attached whether the steps pass or fail
        yield* Effect.gen(function*() {
          yield* page.goto("https://shop.example.com")
          yield* page.getByRole("button", { name: "Add to cart" }).click()
          yield* page.getByText("1 item").pipe(Expect.toBeVisible)
        }).pipe(Effect.ensuring(attachTrace))
      }).pipe(VitestBrowser.withTest(context)))
  }
)
```

A trace captures the test identity when recording starts, so exporting it after a retry or another test starts
keeps the original name, file, project, attempt and repeat. Capture the filename at the same point:

```ts
import { Page, Trace } from "@usestrider/browser"
import { TestRun } from "@usestrider/browser/test"
import { VitestBrowser } from "@usestrider/vitest"
import { Effect } from "effect"

const recordCheckout = Effect.fn("recordCheckout")(function*(page: Page.Page) {
  const { info } = yield* TestRun.TestRun
  const name = VitestBrowser.traceFileName(info)
  const trace = yield* Trace.record(page)
  yield* page.getByRole("button", { name: "Pay" }).click()
  yield* trace.exportTrace(`traces/${name}`)
})
```

`traceFileName` returns a safe ZIP basename with a readable prefix and a SHA-256 digest of the project, file,
test ID, attempt and repeat. Names that produce the same prefix still get distinct digests. The same identity always
gets the same filename; use a separate directory to keep multiple runs or recordings. The manual form keeps recording, exporting
and attaching explicit. The trace header stores test names and file paths as written.
Bind each concurrent callback with `VitestBrowser.withTest(context)` as shown above, so recording and filename
capture use that callback's identity. Without binding, the adapter's global lookup supports sequential tests only.
Concurrent pages within one test keep that test's identity.

`TestRun.TestInfo.repeat` is the zero-based repetition, separate from the retry attempt. Constructors and
decoding default it to zero when omitted. Bind every retry and repeat with `withTest(context)` to capture
both counters. Repeat zero keeps the original trace filename; later repeats add `repeat-N` and include
the repeat in the filename digest and trace metadata.

## A fake browser for events

A real browser decides when a response, a dialog or a crash arrives, so a test can't make one come first, or at
all. `Browser.layerTest` is a fake browser for code about events: waiting for a response, handling a dialog, giving up
when a page crashes. Its first page plays a timeline on Effect's clock, so under `TestClock` it moves only when the
test moves it:

```ts
import { assert, it } from "@effect/vitest"
import { Browser, NetworkResponse, PageNavigation } from "@usestrider/browser"
import { Effect } from "effect"
import { TestClock } from "effect/testing"

const Timeline = Browser.layerTest("--resp(cart)--commit--load--|")

it.effect("sees the cart's response before the page commits", () =>
  Effect.gen(function*() {
    const page = yield* Browser.newPage()
    const cart = yield* NetworkResponse.next(page, { url: "https://example.test/cart" })
    const navigation = yield* PageNavigation.next(page, { waitUntil: "load" })
    yield* TestClock.adjust("20 millis")
    assert.strictEqual((yield* cart).status, 200)
    yield* TestClock.adjust("40 millis")
    assert.strictEqual((yield* navigation)._tag, "Committed")
  }).pipe(Effect.provide(Timeline)))
```

| Token          | Means                                              |
| -------------- | -------------------------------------------------- |
| `-`            | 10 ms                                              |
| `resp(name)`   | a 200 response to `https://example.test/name`     |
| `commit`       | a document commits at `https://example.test/`      |
| `load`         | the document finishes loading                      |
| `dialog(kind)` | a dialog opens, with no message: `alert`, `confirm`, `prompt` or `beforeunload` |
| `popup`        | a popup opens                                      |
| `crash`, `\|`  | the page crashes, or its script closes it          |

- Its events go through the same code as a real browser's.
- It has no DOM: locators fail with [`Unsupported`](/docs/errors#three-kinds-of-failure).
- It's experimental.

A dialog on the timeline is decided as any dialog is, and a crash ends what was waiting on the page. Here a step
of yours accepts the confirm, which on the real site asks "Restore your saved cart?", and reads the cart, or gives
up when the page crashes:

```ts
import { assert, it } from "@effect/vitest"
import {
  AutoResolution,
  Browser,
  Dialog,
  NetworkResponse,
  Page
} from "@usestrider/browser"
import { Effect, Fiber, Option } from "effect"
import { TestClock } from "effect/testing"

const restoreCart = Effect.fn("restoreCart")(function*(page: Page.Page) {
  yield* Dialog.handle(page, Dialog.acceptAll) // the restore confirm
  const cart = yield* NetworkResponse.next(page, { url: "https://example.test/cart" })
  return yield* cart.pipe(
    Effect.map((response) => Option.some(response.status)),
    Effect.catchTag("TargetGone", () => Effect.succeedNone)
  )
})

it.effect("gives up on the cart when the page crashes", () =>
  Effect.gen(function*() {
    const page = yield* Browser.newPage()
    const status = yield* Effect.forkChild(restoreCart(page))
    yield* TestClock.adjust("40 millis")
    assert.isTrue(Option.isNone(yield* Fiber.join(status)))
    const decidedByDefault = yield* AutoResolution.history(page, { subject: "Dialog" })
    assert.strictEqual(decidedByDefault.entries.length, 0)
  }).pipe(Effect.provide(Browser.layerTest("--dialog(confirm)--crash"))))
```

Provide the fake to each test rather than through `layer`, so each test's first page plays its timeline from the
start, on the `TestClock` that `it.effect` gives it.
