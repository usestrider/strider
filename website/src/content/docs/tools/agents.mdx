## Snapshots

A snapshot is a page's accessibility tree as data, with a ref for each node that can be acted on. `text` renders
it for a model:

```ts
import { Page } from "@usestrider/browser"
import { Console, Effect, Option } from "effect"

const clickByName = Effect.fn("clickByName")(function*(page: Page.Page, name: string) {
  const snapshot = yield* page.snapshot({ interactiveOnly: true })
  yield* Console.log(snapshot.text)
  for (const [id, node] of snapshot.refs) {
    if (node.name._tag !== "None" && node.name.value === name) {
      return yield* snapshot.ref(id).click().pipe(Effect.as(Option.some(id)))
    }
  }
  return Option.none()
})
```

- By default a snapshot also infers what the accessibility tree misses: interactivity from `cursor: pointer`,
  `tabindex`, `contenteditable` or `onclick`, and names from text, `title`, `placeholder`, `alt` or a nearby label.
  Each inference is tagged: `clickable "Save" [inferred: cursorPointer]`.
- `snapshot({ sources: "aria" })` is the accessibility tree alone, as `Expect.toMatchAria` matches.
- A ref is a locator pinned to one node, never resolved again. If the node is removed or its document replaced,
  acting on it fails with `StaleRef`, saying which.
- A node keeps its ref while its document lives, even if its name changes.
- `snapshot.diff(previous)` says what changed between two snapshots of a document.

## The toolkit

`BrowserToolkit` gives a model `effect/ai` tools over one context. The same tools serve your program, an MCP server
and the `strider` command:

```ts
import { Browser } from "@usestrider/browser"
import { BrowserToolkit, CapturePolicy } from "@usestrider/browser/ai"
import { Config, Effect } from "effect"
import { LanguageModel } from "effect/ai"

const agent = Effect.scoped(Effect.gen(function*() {
  const context = yield* Browser.newContext()
  const toolkit = yield* BrowserToolkit.make({
    context,
    secrets: { password: yield* Config.Redacted("APP_PASSWORD") },
    capture: CapturePolicy.strict
  })
  const response = yield* LanguageModel.generateText({
    prompt: "On app.example.com, sign in as ada@example.com with %password%.",
    toolkit
  })
  return response.text
}))
```

The tools: `pages`, `newPage`, `tabs`, `control`, `release`, `goto`, `back`, `snapshot`, `find`, `screenshot`,
`click`, `fill`, `press`, `select`, `scroll`, `next`, `await`, `expect`, `history`, `route` and `dialog`.

- **Every tool names its page.** There's no current tab. Pages are named when created (`p1`, `p2`, or the model's
  name) or when first seen, as a popup is.
- **A target is a ref or a locator:** `e12` from the page's latest snapshot, or `role=button[name="Save"]`,
  `text="Add to cart"`, `label=Email`, `testid=cart`, `css=…`. A ref from another page's snapshot is refused.
- **No tool waits after it acts.** `next` subscribes and `await` collects; `expect` waits for a condition.
- **Each result has the outcome and what happened since the last call:** navigations, popups, dialogs and who
  decided them, downloads, uncaught exceptions, console errors, failed requests.
- **Failures go back to the model** as data, hint included.
- **Secrets are named.** The model writes `%password%`; the value is substituted as the tool runs, and results show
  `%password%`.

`capture` is required. `CapturePolicy.strict` sends no screenshots, masks editable fields' text in snapshots as
`•••`, and leaves out console text. `CapturePolicy.local` allows all three.

With `browser` also given, `tabs` and `control` reach the browser's other pages, such as an attached browser's
tabs. Without it, the model stays in its context.

## The strider command

`strider` drives a live browser from a shell. A session holds one browser between commands:

```sh
strider start --name shop --chromium /usr/bin/chromium
strider -s shop page new --name main https://shop.example.com
strider -s shop -p main snapshot
strider -s shop -p main click e9
strider -s shop -p main fill 'label=Email' "ada@example.com"
strider -s shop -p main find "Add to cart" --role button
strider -s shop stop
```

Every command names its session with `-s` and its page with `-p`; there's no default, so agents on one machine
can't act on each other's tabs. Commands are the toolkit's tools, and answer the same way:

```
clicked e9 on main · 412 ms
since last: main navigated to https://shop.example.com/cart · GET https://shop.example.com/api/offers answered 503
```

`next` subscribes and prints a wait handle; `await` collects it in a later command:

```sh
strider -s shop -p main next download --within 2m
strider -s shop -p main click 'role=button[name="Export CSV"]'
strider -s shop await w1
```

A failure prints its tag, message and hint, and exits with the error's code: 10 for `LocatorError`, 12 for
`Timeout`, 14 for `ExpectationFailed`, and others.

### Sessions and state

| Command                                          | Does                                                          |
| ------------------------------------------------ | ------------------------------------------------------------- |
| `strider browsers`                               | lists the browsers on the machine, by path                     |
| `strider start --name s --chromium <path>`       | starts a session; also `--firefox`, `--webkit` or `--attach <endpoint>` |
| `strider sessions`                               | lists sessions, with their pages, idle time and owner          |
| `strider -s s state save ./auth/shop.state`      | saves the session's storage state                              |
| `strider start --name t --chromium <path> --state ./auth/shop.state` | starts another session from it          |
| `strider start --name t --chromium <path> --fork s` | starts one from a running session's state                   |
| `strider -s s tabs`, `control <id> --name mail`  | lists the browser's other tabs, and takes one by name          |
| `strider -s s export test checkout.test.ts`      | writes what the session did as a Vitest test                   |
| `strider -s s stop`                              | ends the session and deletes its directory                     |
| `strider prune`                                  | lists what crashed programs left behind; `--yes` cleans it up  |

- A session's profile, downloads and artifacts are in `$XDG_RUNTIME_DIR/strider/<name>/`, deleted when it stops.
- `--secret password=APP_PASSWORD` at start reads a secret from the environment, used as `%password%` and never
  echoed or recorded.

### Segments

A segment is a TypeScript file run in the live session. Its default export is an `Effect` that finds pages by
name:

```ts title="pay.ts"
import { Popup } from "@usestrider/browser"
import { CurrentSession } from "@usestrider/browser/cli"
import { Effect } from "effect"

export default Effect.gen(function*() {
  const session = yield* CurrentSession.CurrentSession
  const shop = yield* session.page("main")
  const popups = yield* Popup.next(shop)
  yield* shop.getByText("Pay").click()
  const popup = yield* popups
  yield* popup.getByLabel("Card number").fill("4242 4242 4242 4242")
  return { popup }
})
```

```sh
npx tsc --noEmit && strider -s shop run pay.ts
```

- A segment runs in its own scope: its routes, handlers and waits end with it.
- Pages it returns are named into the session under their keys. A popup of a session page stays open; a page the
  segment opened itself closes with it unless `session.keep(page)` keeps it.
- `strider run` doesn't type-check; run your project's `tsc`, against the version the session runs.

### MCP

`strider mcp` serves a session's tools over the Model Context Protocol, sharing the session with your shell:

```json
{
  "mcpServers": {
    "strider": { "command": "strider", "args": ["mcp", "-s", "shop"] }
  }
}
```

`["mcp", "--start", "--chromium", "/usr/bin/chromium"]` starts a session of the client's own, ending with it.
