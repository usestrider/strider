## Spans first

Every operation opens a span named for it, such as `Locator.click` or `Page.goto`, with attributes such as the
page's id, the locator and a redacted URL. They nest under your `Effect.fn` steps and go to whatever tracer Effect
has: `effect/observability` exports OTLP, and Effect's DevTools shows them live.

Traces and HAR files add what spans can't carry: what the page looked like, and the network traffic.

## Traces

`Trace.record` records a page or context for Playwright's trace viewer. Open the file at
[trace.playwright.dev](https://trace.playwright.dev): each operation is a step under your spans, with console
output and errors, and optionally screenshots, network and DOM snapshots.

```ts
import { Browser, Trace } from "@usestrider/browser"
import { Effect } from "effect"

const recorded = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage()
  const trace = yield* Trace.record(page, {
    screenshots: "perAction",
    network: true,
    domSnapshots: true
  })
  yield* page.goto("https://shop.example.com")
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  yield* page.getByRole("link", { name: "Cart" }).click()
  yield* trace.exportTrace("traces/cart.zip")
}))
```

Each capture is opt-in:

| Option                       | Adds                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| none                         | operations, logs, errors and console output                           |
| `screenshots: "perAction"`   | a screenshot after each action                                        |
| `screencast`                 | frames of the page as it renders: `"native"`, or `{ polled: interval }` |
| `network: true`              | the page's requests and responses                                     |
| `domSnapshots: true`         | each frame's DOM before and after every action, which the viewer renders; needs `network` |

DOM snapshots change nothing in the page, and work on an inspected page. They're taken in an isolated world,
except on WebKit, which has none.

## HAR files

`Har.record` records a page's or context's requests as HAR 1.2, one entry per redirect hop. `content` is required:
`"embed"` puts bodies in the file, `"attach"` writes a zip with them beside it, `"omit"` leaves them out:

```ts
import { Browser, Har } from "@usestrider/browser"
import { Effect } from "effect"

const traffic = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage()
  const har = yield* Har.record(page, { content: "embed", url: "**/api/**" })
  yield* page.goto("https://shop.example.com")
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  yield* har.exportHar("fixtures/api.har", { include: ["requestBodies"] })
}))
```

- Timings come from Strider's clock, so they compare across browsers.
- A recording stops when its scope closes; `entries` counts what it has.
- A request in flight at export is marked incomplete, unless `inFlightAtStop: "wait"`.
- A HAR with request bodies can answer the same requests later:
  [`Route.fromHar`](/docs/events/routes#replaying-a-recording).

## What exports leave out

A HAR's export redacts each class of secret unless `include` names it:

| Class                    | Redacted unless included                                   |
| ------------------------ | ---------------------------------------------------------- |
| `"credentials"`          | credentials in URLs                                        |
| `"cookies"`              | cookie values, in `Cookie` and `Set-Cookie`                |
| `"authorizationHeaders"` | `Authorization` headers                                    |
| `"requestBodies"`        | the bodies requests sent, which can hold a password        |

- A trace follows the diagnostics preset. Under `strict`, the default, DOM snapshots write password fields and
  fields filled with a `Redacted` value as `REDACTED`.
- Screenshots, bodies and DOM snapshots hold whatever the page showed. Treat them as a screen recording.
