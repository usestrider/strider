## Chromium and CDP

The Chromium backend drives Chromium, Chrome and Edge over the Chrome DevTools Protocol, and supports nearly every
capability Strider has. The protocol code is generated from Chrome 155; the tests run Chromium 155.0.8059.79.
Nothing checks the version at launch.

## Launching

`Chromium.layer` talks to the browser over a pipe, which has no message size limit:

```ts
import { NodeServices } from "@effect/platform-node"
import { Chromium } from "@usestrider/browser/chromium"
import { Config, Layer } from "effect"

const ChromiumLive = Chromium.layerConfig({
  executablePath: Config.String("CHROMIUM_PATH")
}).pipe(Layer.provide(NodeServices.layer))
```

- Arguments, in order: the launch profile's switches, `--headless` (unless `headless: false`), your `args`,
  `--remote-debugging-pipe`, `--user-data-dir` with a temporary profile, `about:blank`.
- Don't put a URL in `args`: headless Chromium opens one page only.
- `LaunchProfile.automation`, the default, turns off first-run pages, sync, updates and background networking.
  Pages can't tell. `LaunchProfile.concurrent` also stops throttling background pages, which pages can tell.
  `LaunchProfile.stock` adds nothing.
- Headless Chromium's user agent says `HeadlessChrome`. Set `emulation: { userAgent }` to change it.
- With `userDataDir`, the profile's logins are in the default context, not the new one `Browser.newPage()` makes.
  Open a page there:

```ts
import { Browser } from "@usestrider/browser"
import { Effect } from "effect"

const signedIn = Effect.gen(function*() {
  const browser = yield* Browser.Browser
  const everyday = yield* browser.defaultContext.control
  return yield* everyday.newPage
})
```

## Popups

Chromium renders nothing for a page behind another in its window, so each page Strider opens gets its own window.
A popup, though, goes in front of its opener, which stops rendering, and actions on the opener time out. Call
`page.activate` on the opener, or make the context with `focus: "emulated"`:

```ts
import { Browser, Expect, Popup } from "@usestrider/browser"
import { Effect } from "effect"

const signInWithPopup = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage({ focus: "emulated" })
  yield* page.goto("https://app.example.com")
  const popups = yield* Popup.next(page)
  yield* page.getByRole("button", { name: "Sign in with Example" }).click()
  const popup = yield* popups
  yield* popup.getByRole("button", { name: "Allow" }).click()
  yield* page.getByText("Signed in").pipe(Expect.toBeVisible)
}))
```

`focus: "emulated"` makes every page report that it has focus, so it isn't the default.

## Attaching

```sh
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-debug
```

```ts
import { NodeSocket } from "@effect/platform-node"
import { Chromium } from "@usestrider/browser/chromium"
import { Layer } from "effect"

const Attached = Chromium.layerConnect("http://127.0.0.1:9222").pipe(
  Layer.provide(NodeSocket.layerWebSocketConstructor)
)
```

- Recent Chrome won't open a debugging port on the everyday profile: give it its own `--user-data-dir`.
- An HTTP endpoint is read for its WebSocket at `/json/version`. `headers` go with both requests.
- Existing tabs are observed; `inspect` or `control` gives access for a scope. The browser and its tabs stay as
  they were after the program; contexts Strider created close with the connection.
- Several clients can attach at once.
- The browser's own tabs keep Chromium's behaviour: no dialog policy, downloads canceled, no focus emulation.
- Popups aren't paused when they open.
- A dialog an earlier client left open goes unreported, and `inspect` on that page fails with a hint saying so.

## What's different

**Request events lack `Cookie`.** `NetworkResponse.headers` include `Set-Cookie`, but `NetworkRequest.headers` don't
include `Cookie`. Use `NetworkRequest.headersSent`.

**A navigated-away page's body is dropped,** unless a HAR recording or a subscription with `body` collects it.

**Routes see CORS preflights,** the `OPTIONS` requests, on Chromium only. A route for such a URL must answer or
continue them.

**A cut-off favicon request never ends.** A HAR marks it incomplete; `inFlightAtStop: "wait"` waits until the
deadline.

**`back` can restore a cached page,** reported as `Restored`, not `Committed`.

**A failed navigation's document is Chromium's error page,** not a navigation of its own.

**Native HTML drag and drop works.** `html: "synthetic"` works too, but Chromium ignores a script's `dropEffect`.

**Cross-site frames render only in view,** so actions scroll each iframe into view first.

## The raw protocol

`@usestrider/browser/cdp` has 56 CDP domains as typed values, generated from Chrome 155; `CdpConnection` runs them:

```ts
import { Page, Target } from "@usestrider/browser/cdp"
import { CdpConnection, Protocol, Transport } from "@usestrider/browser/protocol"
import { Effect, Stream } from "effect"

const visit = Effect.fn("visit")(function*(endpoint: string, url: string) {
  const transport = yield* Transport.webSocket(endpoint)
  const cdp = yield* CdpConnection.make(transport)
  const { targetId } = yield* Target.createTarget({ url: "about:blank" }).pipe(
    Protocol.on(cdp.browser)
  )
  const attached = Target.attachToTarget({ targetId, flatten: true })
  const { sessionId } = yield* attached.pipe(Protocol.on(cdp.browser))
  const page = yield* cdp.session(sessionId)
  const loaded = yield* page.subscribe(Page.loadEventFired)
  yield* Page.enable().pipe(Protocol.on(page))
  yield* Page.navigate({ url }).pipe(Protocol.on(page))
  yield* Stream.runHead(loaded)
})
```

- No domains are enabled and nothing is tracked or waited for.
- Commands wait 30 seconds for a reply; `Protocol.withCommandTimeout` changes it.
- A Strider page doesn't expose its CDP session. Attach a raw connection to the same browser's debugging port.
- `Browser.TraceProtocolCommands` adds a span for each command Strider sends.

A rejected command fails with `BackendFailure`; its `cause` is the `ProtocolError`, with Chromium's code and message.
