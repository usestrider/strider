Firefox can do less than Chromium, and does some things differently. Within those limits, a program written against
`Browser` runs on it unchanged.

## Protocol and versions

Strider drives Firefox over WebDriver BiDi, the W3C's automation protocol and the only one Firefox has. BiDi covers
less than CDP, so most of what Firefox can't do in Strider is missing from BiDi or from Firefox's implementation of
it; the [Limits](#limits) say which. The tests run Firefox 158.0.

## Launching

`Firefox.layer` connects to the browser over a WebSocket, so it needs a `WebSocketConstructor` as well as the usual
[services](/docs/installation#platform-services). To see Firefox as a person's install shows it, with their profile and devtools open:

```ts
import { NodeServices, NodeSocket } from "@effect/platform-node"
import { LaunchProfile } from "@usestrider/browser"
import { Firefox } from "@usestrider/browser/firefox"
import { Layer } from "effect"

const AdasFirefox = Firefox.layer({
  executablePath: "/usr/bin/firefox",
  headless: false,
  userDataDir: "./profiles/ada",
  profile: LaunchProfile.stock,
  args: ["--devtools"]
}).pipe(Layer.provide([NodeServices.layer, NodeSocket.layerWebSocketConstructor]))
```

- It runs `--headless` (unless `headless: false`), `--remote-debugging-port=0`, `--no-remote`, `--profile` with a
  temporary profile, then your `args`.
- No endpoint within 30 seconds fails the layer with [`ConnectionFailed`](/docs/api/browser/Browser#ConnectionFailed), or
  [`ProcessExited`](/docs/api/browser/Browser#ProcessExited) if Firefox exited.
- On Firefox, a launch profile is the preferences it writes to the profile's `user.js`; its Chromium switches are
  ignored. `LaunchProfile.automation`, the default, writes: no first-run page,
  no updates, no telemetry, the JSON viewer and new-tab preloading off, and popups opened as windows.
- `LaunchProfile.stock` sets nothing, for Firefox as a person's install shows it, with its first-run page, JSON
  viewer, and popups in tabs. [`LaunchProfile.concurrent`](/docs/tools/testing#concurrent-pages) also turns off
  background timer throttling, for pages that run side by side.
- A `userDataDir` of your own is never deleted. Its `user.js` keeps its own preferences; Strider's go in a block
  after them, replaced at each launch.

## Pages as windows

Firefox renders a background tab about once a second, too seldom for an action to wait on. So each page Strider
opens is its own window, and the default profile opens popups as windows too.

A tab of an attached Firefox, or a popup under `LaunchProfile.stock`, is still a tab: call `yield* page.activate`
before acting on it, as [Attaching](#attaching) shows. [`focus: "emulated"`](/docs/tools/testing#concurrent-pages) isn't available on Firefox.

## Attaching

Attaching works as in [Attached browsers](/docs/pages/attaching), at the remote agent's `ws://` endpoint.
Firefox takes one client at a time, through a BiDi session, which Strider opens when the layer is built and ends
when its scope closes.

```sh
firefox --remote-debugging-port=9222
```

```ts
import { NodeSocket } from "@effect/platform-node"
import { Browser } from "@usestrider/browser"
import { Firefox } from "@usestrider/browser/firefox"
import { Effect, Layer } from "effect"

const Attached = Firefox.layerConnect("ws://127.0.0.1:9222").pipe(
  Layer.provide(NodeSocket.layerWebSocketConstructor)
)

const archiveFirst = Effect.fn("archiveFirst")(
  function*() {
    const browser = yield* Browser.Browser
    for (const tab of yield* browser.pages) {
      if ((yield* tab.url).startsWith("https://mail.example.com")) {
        const mail = yield* tab.control
        yield* mail.activate
        yield* mail.getByRole("button", { name: "Archive" }).first.click()
      }
    }
  },
  Effect.scoped,
  Effect.provide(Attached)
)
```

- `/session` is added to an endpoint with no path.
- Existing tabs are observed; [`inspect` or `control`](/docs/pages/attaching#access-levels) gives access for a
  scope. They stay open after the program.
- One session at a time: while another client holds it, connecting fails with `ConnectionFailed`. A session
  outlives its connection, so a program that dies without ending it leaves Firefox refusing clients until it
  restarts; for a browser the `strider` CLI started, [`strider prune --yes`](/docs/agents/cli#managing-sessions)
  stops it.
- Strider's preferences don't apply: the JSON viewer stays on, and tabs are tabs.
- File choosers are left to the browser: the setting that answers them is browser-wide.
- [`Capability.Video`](#differences) isn't available: Firefox writes the file on its own machine.

## Memory in long sessions

Measured on Firefox 158.0, a session that opens and closes many pages grew by about 10 MB per page in Firefox's main process, because Firefox keeps part of every closed window. About half was freed after roughly 30 seconds idle, and a busy session never idles that long. Restarting the browser releases it, so a session that opens thousands of pages should relaunch Firefox now and then, between tasks.

## Differences

**[Init scripts](/docs/events/init-scripts) given as `{ source }` or `{ path }` run inside a function,** so their
top-level `var` and function declarations aren't globals. Assign to `window` to share something.

**Bodies need a subscription first.** BiDi keeps a body only if collection was set up before the request started,
by a subscription with [`body`](/docs/events/network#decoding-bodies) or by
[`Har.record`](/docs/tools/recordings#har-files).

**Pointer events land on whole pixels.** Strider sends the exact point an action picks, but Firefox delivers it
at the nearest whole pixel, so a click at a fractional point, such as an explicit `position` in a box at a
half-pixel offset, lands up to half a pixel away. The capability `input.fractionalPointer` is `partial` here.

**An unhandled rejection is reported as a throw,** so [`UncaughtException`](/docs/events/events#history)'s `kind` is `"unknown"`.

**[`servedBy`](/docs/events/network#response-sources) is `"cacheOrServiceWorker"`** for both: Firefox can't tell them apart. A script reused from the memory
cache shows up as a request.

**Console text is Firefox's own formatting,** which writes `%f` as printf does: `1.250000`.

**Typing is key by key.** [Keyboard layouts](/docs/pages/actions#keys) send no AltGr or dead keys, and the page
sees a US key's `code`. [`insertText`](/docs/pages/actions#the-keyboard-and-the-mouse) types each character as a
key.

**HTML drag and drop needs [`html: "synthetic"`](/docs/pages/actions#dragging):** Firefox starts a native drag but never drops it.

**Input into a cross-site frame goes to the frame's document,** since Firefox doesn't route page coordinates into
it. A drag between documents goes to the first one alone.

**[Routes](/docs/events/routes) do less.** No sending a request to a new URL, no fulfilling at the response phase
(changing status and headers works), and no abort reason but `"failed"`: a decision Firefox can't apply fails with
`Unsupported`, and the request continues as it was.

**Video, not frames.** [`Capability.Video`](/docs/api/browser/Capability#Video) records a WebM file into the context's downloads
directory; [`Capability.Screencast`](/docs/api/browser/Capability#Screencast) isn't available. A trace's
[`screencast: "native"`](/docs/tools/recordings#traces) uses the video. Firefox needs no
[`VideoWriter`](/docs/tools/video#what-each-browser-needs), unlike Chromium. To record one around a step, take the
capability for that scope with `page.capability`:

```ts
import { Capability, Page } from "@usestrider/browser"
import { Effect } from "effect"

const recordCheckout = Effect.fn("recordCheckout")(function*(page: Page.Page) {
  const video = yield* Effect.scoped(Effect.gen(function*() {
    const recording = yield* page.capability(Capability.Video)
    yield* page.getByRole("button", { name: "Pay" }).click()
    return recording
  }))
  return yield* video.file // written once the recording's scope closes
})
```

## Other WebDriver BiDi browsers

`Firefox.layerConnect` expects Firefox. For a BiDi browser on a grid, whose endpoint is already a session URL, use
`Bidi.layerConnect`: it takes the endpoint as given, with handshake headers such as the grid's token:

```ts
import { NodeSocket } from "@effect/platform-node"
import { Bidi } from "@usestrider/browser/bidi"
import { Config, Effect, Layer } from "effect"

const Grid = Layer.unwrap(Effect.gen(function*() {
  const token = yield* Config.Redacted("GRID_TOKEN")
  return Bidi.layerConnect("wss://grid.example.com/session", {
    headers: { authorization: token }
  })
})).pipe(Layer.provide(NodeSocket.layerWebSocketConstructor))
```

Only Firefox is tested:

- The capability list is Firefox's, whatever browser answers.
- It always starts a new session; an endpoint that hands out an existing session's socket may refuse.
- Attached connections copy [`FileInput.local`](/docs/pages/actions#files) contents from the caller, using captured
  file-system and path [platform services](/docs/installation#platform-services).
  [`FileInput.remote`](/docs/api/browser/FileInput#remote) instead names a file already on the browser host.
- Safari Technology Preview's BiDi is partial, and needs a WebDriver capability Strider doesn't set.

## The raw protocol

Use the raw protocol for a BiDi command Strider has no operation for, such as installing a web extension. It needs
Firefox's one session, so it runs instead of Strider, not beside it. `@usestrider/browser/bidi-protocol` has every
BiDi command and event as a typed value; `BidiConnection` runs them, at the session endpoint, such as
`ws://127.0.0.1:9222/session`:

```ts
import { Session, WebExtension } from "@usestrider/browser/bidi-protocol"
import { BidiConnection, Protocol, Transport } from "@usestrider/browser/protocol"
import { Effect } from "effect"

const installExtension = Effect.fn("installExtension")(
  function*(endpoint: string, path: string) {
    const transport = yield* Transport.webSocket(endpoint)
    const bidi = yield* BidiConnection.make(transport)
    const on = Protocol.on(bidi.session)
    yield* Session.new_({ capabilities: {} }).pipe(on)
    // End the session even on failure, or Firefox stays locked
    yield* Effect.addFinalizer(() => Session.end().pipe(on, Effect.ignore))
    const { extension } = yield* WebExtension.install({
      extensionData: { type: "path", path }
    }).pipe(on)
    return extension
  },
  Effect.scoped
)
```

- Nothing is tracked or waited for.
- To find the BiDi commands a Strider step sends, provide
  [`Browser.TraceProtocolCommands`](/docs/api/browser/Browser#TraceProtocolCommands) as `true` around it.

A raw command Firefox rejects fails with a
[`ProtocolError`](/docs/api/browser/protocol/Protocol#ProtocolError) whose reason, `Rejected`, has Firefox's
`code`, such as `"no such frame"`, and `description`, and a `reason` read from them: `NoSuchTarget`,
`NoSuchFrame`, `NoSuchNode`, `InvalidArgument`, or `Unrecognized` for any other. A command Strider sends fails its
operation with [`BackendFailure`](/docs/errors#three-kinds-of-failure), the `ProtocolError` as its `cause`.
