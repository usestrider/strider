## Firefox and WebDriver BiDi

Strider drives Firefox over WebDriver BiDi, the W3C's automation protocol and the only one Firefox has. BiDi covers
less than CDP, so most of what Firefox can't do in Strider is missing from BiDi or from Firefox's implementation of
it; the [list below](#what-firefox-cant-do) says which. The tests run Firefox 158.0.

## Launching

`Firefox.layer` connects to the browser over a WebSocket, so it needs a `WebSocketConstructor` as well as the usual
services:

```ts
import { NodeServices, NodeSocket } from "@effect/platform-node"
import { Firefox } from "@usestrider/browser/firefox"
import { Config, Layer } from "effect"

const FirefoxLive = Firefox.layerConfig({
  executablePath: Config.String("FIREFOX_PATH")
}).pipe(Layer.provide([NodeServices.layer, NodeSocket.layerWebSocketConstructor]))
```

- It runs `--headless` (unless `headless: false`), `--remote-debugging-port=0`, `--no-remote`, `--profile` with a
  temporary profile, then your `args`.
- No endpoint within 30 seconds fails the layer with `ConnectionFailed`, or `ProcessExited` if Firefox exited.
- `LaunchProfile.automation`, the default, writes preferences to the profile's `user.js`: no first-run page,
  updates or telemetry, the JSON viewer off, and popups opened as windows.
- `LaunchProfile.stock` sets nothing. `LaunchProfile.concurrent` also turns off background timer throttling.
- A profile's `args` are Chromium switches; Firefox ignores them.
- A `userDataDir` of your own is never deleted. Its `user.js` keeps its own preferences; Strider's go in a block
  after them, replaced at each launch.

## Pages are windows

Firefox renders a background tab about once a second, too seldom for an action to wait on. So each page Strider
opens is its own window, and the default profile opens popups as windows too.

A tab of an attached Firefox, or a popup under `LaunchProfile.stock`, is still a tab: call `yield* page.activate`
before acting on it. `focus: "emulated"` isn't available on Firefox.

## Attaching

```sh
firefox --remote-debugging-port=9222
```

```ts
import { NodeSocket } from "@effect/platform-node"
import { Browser } from "@usestrider/browser"
import { Firefox } from "@usestrider/browser/firefox"
import { Effect, Layer } from "effect"

const Attached = Firefox.layerConnect("ws://127.0.0.1:9222").pipe(
  Layer.provide(NodeSocket.layerWebSocketConstructor)
)

const tabTitles = Effect.scoped(Effect.gen(function*() {
  const pages = yield* (yield* Browser.Browser).pages
  return yield* Effect.forEach(
    pages,
    (page) => Effect.flatMap(page.inspect, (tab) => tab.title)
  )
})).pipe(Effect.provide(Attached))
```

- `/session` is added to an endpoint with no path.
- Existing tabs are observed; `inspect` or `control` gives access for a scope. They stay open after the program.
- **One session at a time.** A session outlives its connection until something ends it. Strider ends its own when
  the layer's scope closes. While another client holds it, connecting fails with `ConnectionFailed`. A program that
  dies without ending its session leaves Firefox refusing clients until it restarts; for a `strider` session,
  `strider prune --yes` stops the browser.
- Strider's preferences don't apply: the JSON viewer stays on, and tabs are tabs.
- File choosers are left to the browser: the setting that answers them is browser-wide.
- `Capability.Video` isn't available: Firefox writes the file on its own machine.

## What's different

**Init scripts run inside a function,** so top-level `var` and function declarations aren't globals. Assign to
`window` to share something.

**Bodies need a subscription first.** BiDi keeps a body only if collection was set up before the request started,
by a subscription with `body` or by `Har.record`.

**An unhandled rejection is reported as a throw,** so `UncaughtException`'s `kind` is `"unknown"`.

**`servedBy` is `"cacheOrServiceWorker"`** for both: Firefox can't tell them apart. A script reused from the memory
cache shows up as a request.

**Console text is Firefox's own formatting,** which writes `%f` as printf does: `1.250000`.

**Typing is key by key.** Keyboard layouts send no AltGr or dead keys, and the page sees a US key's `code`.
`insertText` types each character as a key.

**HTML drag and drop needs `html: "synthetic"`:** Firefox starts a native drag but never drops it.

**Input into a cross-site frame goes to the frame's document,** since Firefox doesn't route page coordinates into
it. A drag between documents goes to the first one alone.

**Routes do less.** No sending a request to a new URL, no fulfilling at the response phase (changing status and
headers works), and every abort is `"failed"`. An unanswered authentication challenge is canceled.

**Video, not frames.** `Capability.Video` records a WebM file into the context's downloads directory;
`Capability.Screencast` isn't available. A trace's `screencast: "native"` uses the video.

## Other WebDriver BiDi browsers

`Bidi.layerConnect` takes any BiDi endpoint as given, with handshake headers such as a grid's token:

```ts
import { NodeSocket } from "@effect/platform-node"
import { Bidi } from "@usestrider/browser/bidi"
import { Config, Effect, Layer } from "effect"

const Grid = Layer.unwrap(Effect.gen(function*() {
  const token = yield* Config.Redacted("GRID_TOKEN")
  return Bidi.layerConnect("wss://grid.example.com/session", {
    headers: { authorization: token }
  })
})).pipe(Layer.provide(NodeSocket.layerWebSocketConstructor))
```

Only Firefox is tested:

- The capability list is Firefox's, whatever browser answers.
- It always starts a new session; an endpoint that hands out an existing session's socket may refuse.
- A remote browser can't read `FileInput.local` paths: use `FileInput.bytes`, or `FileInput.remote`.
- Safari Technology Preview's BiDi is partial, and needs a WebDriver capability Strider doesn't set.

## The raw protocol

`@usestrider/browser/bidi-protocol` has every BiDi command and event as a typed value; `BidiConnection` runs them:

```ts
import { BrowsingContext, Session } from "@usestrider/browser/bidi-protocol"
import { BidiConnection, Protocol, Transport } from "@usestrider/browser/protocol"
import { Effect } from "effect"

const openTab = Effect.fn("openTab")(function*(endpoint: string, url: string) {
  const transport = yield* Transport.webSocket(endpoint)
  const bidi = yield* BidiConnection.make(transport)
  yield* Session.new_({ capabilities: {} }).pipe(Protocol.on(bidi.session))
  const { context } = yield* BrowsingContext.create({ type: "tab" }).pipe(
    Protocol.on(bidi.session)
  )
  yield* BrowsingContext.navigate({ context, url, wait: "complete" }).pipe(
    Protocol.on(bidi.session)
  )
})
```

- Nothing is tracked or waited for.
- Firefox's one session means a raw connection can't run beside Strider's.
- End your session with `Session.end` before closing, or Firefox stays locked.
- `Browser.TraceProtocolCommands` adds a span for each command Strider sends.

A rejected command fails with `BackendFailure`; its `cause` is the `ProtocolError`, with Firefox's code and message.
