A Strider program needs three things it doesn't choose for you: a browser to run, the backend that drives it, and
the platform services the backend starts it with.

## The packages

```sh
npm install @usestrider/browser effect @effect/platform-node
```

| Package                 | What it's for                                                                       |
| ----------------------- | ----------------------------------------------------------------------------------- |
| `@usestrider/browser`   | Strider, its backends as subpaths, and the `strider` command                        |
| `effect`                | Effect 4, a peer dependency                                                          |
| `@effect/platform-node` | processes, files and sockets on Node; `@effect/platform-bun` on Bun                 |
| `@usestrider/vitest`    | the Vitest adapter, for [tests](/docs/tools/testing)                                |

Strider depends only on Effect. Platform services are needed only where a browser is launched or connected to.

## A browser

Strider never downloads, installs or looks for a browser: a launch takes an absolute path. Install browsers as
you'd install any program. To find their paths:

```sh
npx strider browsers
npx strider browsers --json
```

It lists browsers on your `PATH`, in Chrome's, Edge's and Firefox's install locations, and WebKit's MiniBrowser
where Linux packages and Nix profiles put it, each with its version. `--json` prints the same as data.

## Backends

A backend speaks one browser's protocol and provides the `Browser` service, which `Browser.newPage()` uses. Each is
an import, so a program loads only the protocol code it uses, and one written against `Browser` runs on any of them
by changing the layer.

| Import                          | Drives                                                         | Layers                                      |
| ------------------------------- | -------------------------------------------------------------- | ------------------------------------------- |
| `@usestrider/browser/chromium`  | Chromium, Chrome and Edge, over the Chrome DevTools Protocol    | `layer`, `layerConfig`, `layerConnect`      |
| `@usestrider/browser/firefox`   | Firefox, over WebDriver BiDi                                    | `layer`, `layerConfig`, `layerConnect`      |
| `@usestrider/browser/webkit`    | WebKitGTK's and WPE's MiniBrowser, launched, or their browsers, attached | `layer`, `layerConfig`, `layerAttach` |
| `@usestrider/browser/bidi`      | any WebDriver BiDi endpoint, such as a remote grid              | `layerConnect`                              |

- `layer` launches a browser with a temporary profile, deleted after it exits. The browser exits when the layer's
  scope closes.
- Chromium and Firefox run headless unless `headless: false`. WebKit has no headless mode.
- `layerConfig` reads the same options from configuration.
- `layerConnect` and `layerAttach` attach to a running browser and leave it running. See
  [Contexts and access](/docs/pages/contexts#attaching-to-a-browser).

```ts
import { Chromium } from "@usestrider/browser/chromium"

const headless = Chromium.layer({ executablePath: "/usr/bin/chromium" })
const headed = Chromium.layer({ executablePath: "/usr/bin/chromium", headless: false })
```

## Paths from configuration

A path in the code is right on one machine only. `layerConfig` takes each option as a `Config`, so each machine
reads its own path from its environment:

```ts
import { Chromium } from "@usestrider/browser/chromium"
import { Config } from "effect"

const BrowserLive = Chromium.layerConfig({
  executablePath: Config.String("CHROMIUM_PATH")
})
```

A missing variable fails the layer with `ConfigError` before anything launches.

## Platform services

A backend's layer starts the browser through Effect's platform services and requires them in its type, so a
program run without them doesn't compile. Provide them to the backend's layer:

| Backend  | Needs                                                                     |
| -------- | ------------------------------------------------------------------------- |
| Chromium | `NodeServices.layer`                                                      |
| Firefox  | `NodeServices.layer` and `NodeSocket.layerWebSocketConstructor`           |
| WebKit   | `NodeServices.layer` and a `SocketConnector` ([how](/docs/browsers/webkit#launching)) |
| Attaching (`layerConnect`, `layerAttach`) | `NodeSocket.layerWebSocketConstructor`   |

On Bun, `BunServices.layer` and `BunSocket.layerWebSocketConstructor`, from `@effect/platform-bun`, take their
places.

```ts
import { NodeServices, NodeSocket } from "@effect/platform-node"
import { Chromium } from "@usestrider/browser/chromium"
import { Firefox } from "@usestrider/browser/firefox"
import { Config, Layer } from "effect"

const ChromiumLive = Chromium.layerConfig({
  executablePath: Config.String("CHROMIUM_PATH")
}).pipe(Layer.provide(NodeServices.layer))

const FirefoxLive = Firefox.layerConfig({
  executablePath: Config.String("FIREFOX_PATH")
}).pipe(Layer.provide([NodeServices.layer, NodeSocket.layerWebSocketConstructor]))
```
