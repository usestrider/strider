Strider is browser automation for [Effect](https://effect.website): scripts, tests and agents that drive Chromium,
Firefox or WebKit. It speaks each browser's protocol directly, so it drives browsers as they're installed, with no
driver or patched build beside them.

WebKit here means WebKitGTK's and WPE's MiniBrowser on Linux, not Safari. Strider is pre-release; the API can still change before 1.0. What a browser
[can't do](/docs/browsers/choosing#capabilities) fails with `Unsupported`, naming the capability.

```ts
import { NodeServices } from "@effect/platform-node"
import { Browser, Expect } from "@usestrider/browser"
import { Chromium } from "@usestrider/browser/chromium"
import { Effect, Layer } from "effect"

const BrowserLive = Chromium.layer({ executablePath: "/usr/bin/chromium" }).pipe(
  Layer.provide(NodeServices.layer)
)

const program = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage()
  yield* page.goto("https://shop.example.com")
  yield* page.getByRole("button", { name: "Add to cart" }).click()
  yield* page.getByText("1 item").pipe(Expect.toBeVisible)
})).pipe(Effect.provide(BrowserLive))
```

A launch runs the executable you name; Strider never finds or installs a browser.
[`strider browsers`](/docs/installation#a-browser) lists the browsers on your machine.

## Differences from Playwright

Pages, [locators](/docs/pages/locators), [`click` and `fill`](/docs/pages/actions) and
[retrying expectations](/docs/pages/expectations) work much as in Playwright. What differs:

### Scoped lifetimes

A page, [route](/docs/events/routes) or [dialog handler](/docs/events/kinds#dialogs-and-file-choosers)
ends with the `Scope` that acquired it, even on failure or interruption.

```ts
import { Browser } from "@usestrider/browser"
import { Effect } from "effect"

const visit = Effect.gen(function*() {
  const page = yield* Browser.newPage()
  yield* page.goto("https://shop.example.com")
}).pipe(Effect.scoped) // The page closes when this scope ends, even if navigation fails.
```

### Subscribing before acting

To catch a popup, download or response an action causes,
[subscribe first](/docs/events/events). A subscription sees events after it starts, never before.

```ts
import { Page, Popup } from "@usestrider/browser"
import { Effect } from "effect"

const openHelp = Effect.fn("openHelp")(function*(page: Page.Page) {
  const nextPopup = yield* Popup.next(page) // Subscribe before clicking.
  yield* page.getByRole("link", { name: "Help" }).click()
  const help = yield* nextPopup // Page.Page: title, getByRole(), goto(), etc.
  return yield* help.title
})
```

### Error reasons and hints

Each module has one [error](/docs/errors), whose `reason` says why, with a `hint`
of what to do, such as `2 elements match and 1 of them is visible; add .filter({ visible: true })`. A failed
expectation has the values it saw instead. Any operation can also fail with `TargetGone` or `Timeout`, both in
its type.

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const save = Effect.fn("save")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Save" }).click().pipe(
    Effect.tapErrorTag("LocatorError", (error) =>
      // Example log messages:
      // "StrictViolation"
      // "2 elements match and 1 of them is visible; add .filter({ visible: true })"
      Effect.logError(error.reason._tag, error.reason.hint))
  )
})
```

### One deadline per operation

Each operation has [one deadline](/docs/deadlines) covering everything it does.
`Deadline.within("5 seconds")` sets one for a block.

```ts
import { Deadline, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const pay = Effect.fn("pay")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Pay" }).click()
  yield* page.getByText("Payment received").pipe(Expect.toBeVisible)
}, Deadline.within("5 seconds")) // One shared budget for both steps.
```

### Typed access

[Access is typed](/docs/pages/attaching#access-levels). A page you opened is a `Page`. A tab of a browser you
attached to can only be watched until you ask for access, and acting on it before then doesn't compile.

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const readTitle = Effect.fn("readTitle")(function*(tab: Page.ObservedPage) {
  const page = yield* tab.inspect
  // yield* page.goto("https://shop.example.com") // Type error: no goto on ReadonlyPage.
  return yield* page.title
})
```

### Explicit behavior

There are no hidden sleeps, grace periods or retries of input that may have reached the page.

[Strider for Playwright users](/docs/playwright) gives Strider's call for each Playwright call that differs.
