A model drives a browser only through tools, and every result a tool returns goes to the model's provider. The
toolkit gives it Strider's tools over one context, with secrets it names but never sees, and a policy for what
results may carry.

## Running an agent

`BrowserToolkit` gives a model `effect/ai` tools over one context. Use it when your program calls the model through
`effect/ai`; when an MCP client, such as an editor's agent, runs the model, serve the same tools with
[`strider mcp`](/docs/agents/cli#mcp). Where [`pickAndClick`](/docs/agents/snapshots#acting-through-refs) gives a
model one action, the toolkit gives it every tool below, and each result says what happened since the last call.
For agents using shell commands, [`strider agent instructions`](/docs/agents/cli#agent-usage) prints a usage guide
and can generate a skill.
An agent runs turns in a `Chat` until one asks for no tool. Set `concurrency: 1` to execute each turn's browser actions in order:

```ts
import { Browser } from "@usestrider/browser"
import { BrowserToolkit, CapturePolicy } from "@usestrider/browser/ai"
import { Config, Effect } from "effect"
import { Chat } from "effect/ai"

const signIn = Effect.fn("signIn")(function*() {
  const context = yield* Browser.newContext()
  const toolkit = yield* BrowserToolkit.make({
    context,
    secrets: {
      password: yield* Config.Redacted("APP_PASSWORD")
    },
    capture: CapturePolicy.strict
  })

  const chat = yield* Chat.fromPrompt(
    "On app.example.com, sign in as ada@example.com with %password%."
  )

  // Run browser tools, then let the model read the results and choose its next step.
  // Stop when it answers without calling tools.
  return yield* chat.generateText({
    prompt: [],
    toolkit,
    concurrency: 1
  }).pipe(
    Effect.repeat({
      until: (turn) => turn.toolCalls.length === 0
    }),
    Effect.map((turn) => turn.text) // Return the final turn's text.
  )
}, Effect.scoped)
```

## Tools

`pages`, `newPage`, `tabs`, `control` and `release` manage the model's pages (`release` gives back a page `control`
took, its routes and handlers ended), and `goto` and `back` navigate. `snapshot`, `find` and `screenshot` read a
page, and `click`, `fill`, `press`, `select` and `scroll` act as [actions](/docs/pages/actions) do. `next`, `await`
and `history` are the [event verbs](/docs/events/events#next-stream-and-history), `expect` an
[expectation](/docs/pages/expectations), `route` a [route](/docs/events/routes) and `dialog` a
[dialog handler](/docs/events/kinds#dialogs-and-file-choosers). A result reads
[as the CLI prints it](/docs/agents/cli#commands).

A click's digest reports `validation observed during click` once per affected control when an `invalid`
event occurs during that click operation. This is temporal evidence only: page handlers can call
`checkValidity()` or `reportValidity()` on unrelated controls, so it does not prove a submission was attempted
or blocked. Repeated clicks can each report validation even when snapshot invalidity is unchanged. Observation
does not call validity methods, change focus, cancel events or wait for later timers.

Observation covers the top document and open shadow roots present when observation starts. It excludes child
frames, closed shadow roots and roots created later. Navigation, document loss or an open dialog can discard observations;
the original click error is preserved. Strict capture shows the control's role and a masked message, without
its name; local capture includes the name and validation message. Snapshot invalidity continues to describe
current validity independently of clicks. Feedback collection shares the click's deadline and interruption.
If collection cannot finish, observer release runs separately and never adds feedback to a later result.
A busy document may retain listeners until it executes the queued release or ends; the caller does not wait for it.


- **Every tool names its page.** There's no current tab. Pages are named when created (`p1`, `p2`, or the model's
  name) or when first seen, as a popup is.
- **A target is a ref or a locator:** `e12` from the page's latest snapshot, or `role=button[name="Save"]`,
  `text="Add to cart"`, `label=Email`, `testid=cart`, `css=…`. A ref from another page's snapshot is refused.
- **Waits for later events are explicit.** `next` subscribes and `await` collects; `expect` waits for a condition.
  Action tools do not add a wait for later page events, but they await browser/protocol completion, which can
  include navigation or a busy page responding. Input completion is not guaranteed to be immediate.
- **Each result has the outcome and what happened since the last call:** navigations, popups, dialogs and who
  decided them, file choosers the policy canceled, closed pages, downloads, uncaught exceptions, failed requests,
  validation observed during clicks, and console errors where the [capture policy](#capture-policy) allows them.
- **Failures go back to the model** as data, hint included.
- **Secrets are named.** The model writes `%password%`; the value is substituted as the tool runs, and results show
  `%password%`. Only the names in `secrets` are substituted: any other text between `%` signs, such as `%C3%` in a
  URL, is sent as written, and so is a mistyped name.

## Capture policy

Every result goes to the model's provider, and a page can hold secrets, or instructions aimed at the model. `capture`
is required: `CapturePolicy.strict`, for production and pages you don't trust, sends no screenshots, masks editable
fields' text in snapshots as `•••`, and leaves console errors out of what a result says happened, while
`history` lists them with "(text not sent)" for their text; `CapturePolicy.local`, for local development against
pages you trust, allows all three. Read the choice from configuration, so only a machine that says so gets
`local`:

```ts
import { UserContext } from "@usestrider/browser"
import { BrowserToolkit, CapturePolicy } from "@usestrider/browser/ai"
import { Config, Effect } from "effect"

const Capture = Config.Literals(["strict", "local"], "AGENT_CAPTURE").pipe(
  Config.withDefault("strict"),
  Config.map((name) => name === "local" ? CapturePolicy.local : CapturePolicy.strict)
)

const agentTools = Effect.fn("agentTools")(function*(context: UserContext.UserContext) {
  return yield* BrowserToolkit.make({
    context,
    secrets: {},
    capture: yield* Capture
  })
})
```

## Browser access

Without `browser`, the model stays in its context. With it, `tabs` and `control` reach the browser's other pages,
such as a tab of an [attached](/docs/pages/attaching) browser you're already signed in to:

```ts
import { NodeSocket } from "@effect/platform-node"
import { Browser } from "@usestrider/browser"
import { BrowserToolkit, CapturePolicy } from "@usestrider/browser/ai"
import { Chromium } from "@usestrider/browser/chromium"
import { Effect, Layer } from "effect"
import { Chat } from "effect/ai"

const MyChrome = Chromium.layerConnect("http://127.0.0.1:9222").pipe(
  Layer.provide(NodeSocket.layerWebSocketConstructor)
)

const tidyMyInbox = Effect.fn("tidyMyInbox")(
  function*() {
    const browser = yield* Browser.Browser
    const context = yield* Browser.newContext()
    const toolkit = yield* BrowserToolkit.make({
      context,
      browser,
      secrets: {},
      capture: CapturePolicy.strict
    })

    const chat = yield* Chat.fromPrompt(
      "In my mail tab, archive the newsletters from this week."
    )

    // Run browser tools, then let the model read the results and choose its next step.
    // Stop when it answers without calling tools.
    return yield* chat.generateText({
      prompt: [],
      toolkit,
      concurrency: 1
    }).pipe(
      Effect.repeat({
        until: (turn) => turn.toolCalls.length === 0
      }),
      Effect.map((turn) => turn.text) // Return the final turn's text.
    )
  },
  Effect.scoped,
  Effect.provide(MyChrome)
)
```

When the model calls `release`, or the step's scope closes, a tab it took with `control` stays open, and its routes
and handlers end. Without `browser`, `tabs` and `control` fail with `NotPermitted`, and the model reads
`This toolkit was made for its context alone; BrowserToolkit.make with the browser lists and controls its tabs`.
