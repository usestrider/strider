Pages that share cookies and storage leak state from one task or test into the next. A context is a session of its
own, so pages in different contexts share nothing, and its settings hold for every page in it.

## Contexts

A context is an isolated session: its own cookies, storage, cache and permissions, like a fresh profile.
`Browser.newPage()` makes a context with one page in it. For pages that share a session, such as two tabs of one
signed-in user, make the context and open pages in it:

```ts
import { Browser, Expect } from "@usestrider/browser"
import { Effect } from "effect"

const twoTabs = Effect.scoped(Effect.gen(function*() {
  const context = yield* Browser.newContext()
  const inbox = yield* context.newPage
  const settings = yield* context.newPage
  yield* inbox.goto("https://mail.example.com")
  yield* settings.goto("https://mail.example.com/settings")
  yield* settings.getByLabel("Display name").fill("Ada")
  yield* settings.getByRole("button", { name: "Save" }).click()
  yield* inbox.reload()
  yield* inbox.getByText("Ada").pipe(Expect.toBeVisible)
}))
```

A context and its pages close with the scope that made them, popups included.

## Settings for the whole session

Options to `newContext` or `newPage` hold for the context's life, and apply before its first page loads:

```ts
import { Browser } from "@usestrider/browser"
import { Effect } from "effect"

const berlinPhone = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage({
    emulation: {
      viewport: { width: 390, height: 844, deviceScaleFactor: 3, mobile: true },
      locale: "de-DE",
      timezone: "Europe/Berlin",
      media: { colorScheme: "dark" }
    },
    permissions: ["geolocation"],
    dialogs: "accept"
  })
  yield* page.goto("https://maps.example.com")
}))
```

| Option           | Sets                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| `emulation`      | viewport, user agent, locale, time zone, position, media features, network, CPU     |
| `permissions`    | permissions granted to every origin                                                |
| `storageState`   | cookies and storage to start from (below)                                          |
| `dialogs`        | what happens to a dialog no handler decides: `"dismiss"` (the default), `"accept"`, `"leaveOpen"` |
| `downloads`      | a temporary directory (the default), `"deny"`, or `{ directory }`                  |
| `focus`          | `"emulated"` makes every page behave as if focused, for many pages at once          |
| `keyboardLayout` | the layout typing uses: `us` (the default), `uk`, `de`, `fr`, `es`, `it`           |
| `eventLog`       | how many past events of each kind `history` keeps per page; 100 unless set           |

A field the browser can't apply, such as touch on Firefox, fails with `Unsupported` naming it, before anything is
applied. `browser.capabilities` lists what a backend can do.

## Settings for a while

`emulate` and `grant`, on a page or a context, apply settings until their scope closes, then restore what was
there:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const offlineBanner = Effect.fn("offlineBanner")(function*(page: Page.Page) {
  yield* Effect.scoped(Effect.gen(function*() {
    yield* page.emulate({ network: "offline" })
    yield* page.getByText("You're offline").pipe(Expect.toBeVisible)
  }))
  yield* page.getByText("You're offline").pipe(Expect.toBeHidden)
})
```

## Logging in once

Storage state is a context's cookies, and the `localStorage` and IndexedDB of each origin it has open.
`exportStorageState` reads it; the `storageState` option starts a context from it, already signed in:

```ts
import { Browser, Expect, StorageState } from "@usestrider/browser"
import { Config, Effect, FileSystem, Schema } from "effect"

const saveLogin = Effect.scoped(Effect.gen(function*() {
  const page = yield* Browser.newPage()
  yield* page.goto("https://app.example.com/login")
  yield* page.getByLabel("Email").fill("ada@example.com")
  yield* page.getByLabel("Password").fill(yield* Config.Redacted("APP_PASSWORD"))
  yield* page.getByRole("button", { name: "Sign in" }).click()
  yield* page.getByText("Welcome").pipe(Expect.toBeVisible)
  const state = yield* page.context.exportStorageState
  const json = yield* Schema.encodeEffect(StorageState.Json)(state)
  const fs = yield* FileSystem.FileSystem
  yield* fs.writeFileString("auth/app.json", json, { mode: 0o600 })
}))

const signedIn = Effect.gen(function*() {
  const fs = yield* FileSystem.FileSystem
  const json = yield* fs.readFileString("auth/app.json")
  const storageState = yield* Schema.decodeEffect(StorageState.Json)(json)
  return yield* Browser.newPage({ storageState })
})
```

- In memory, its secrets are `Redacted`. `StorageState.Json` writes them out in full: keep the file out of version
  control.
- It doesn't carry `sessionStorage`, service workers or logins bound to a device. For those, use a profile
  directory: `Chromium.layer({ executablePath, userDataDir })`.
- A profile's logins are in the default context, not the one `Browser.newPage()` makes. Open the page there:
  `(yield* browser.defaultContext.control).newPage`, with [`control`](/docs/pages/attaching#access-is-typed).

## Cookies and storage

`context.cookies` reads and changes a context's cookies; `page.localStorage` and `page.sessionStorage`, the current
origin's storage:

```ts
import { Page } from "@usestrider/browser"
import { Effect, Option } from "effect"

const betaFlag = Effect.fn("betaFlag")(function*(page: Page.Page) {
  yield* page.context.cookies.set({
    name: "beta",
    value: "1",
    scope: { _tag: "Url", url: "https://app.example.com" }
  })
  const sent = yield* page.context.cookies.listFor("https://app.example.com/api")
  yield* page.localStorage.set("theme", "dark")
  const theme = yield* page.localStorage.get("theme")
  return { cookies: sent.length, theme: Option.getOrElse(theme, () => "light") }
})
```

- `listFor` gives the cookies a request to that URL would send.
- Cookie values are `Redacted`.
- A set cookie stays when the scope closes.
