## Actions

An action is a locator method, with settings as an optional last argument:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const editProfile = Effect.fn("editProfile")(function*(page: Page.Page) {
  yield* page.getByLabel("Name").fill("Ada Lovelace")
  yield* page.getByLabel("Country").selectOption({ label: "United Kingdom" })
  yield* page.getByLabel("Send me the newsletter").check()
  yield* page.getByRole("button", { name: "Save" }).click()
  const row = page.getByRole("row").filter({ hasText: "Ada Lovelace" })
  yield* row.click({ button: "right" })
})
```

| Action                        | Does                                                                      |
| ----------------------------- | ------------------------------------------------------------------------- |
| `click()`, `dblclick()`       | moves the pointer to the element, presses and releases                     |
| `tap()`                       | a touch start and end                                                      |
| `hover()`                     | moves the pointer over the element                                         |
| `check()`, `uncheck()`        | clicks a checkbox or radio unless it's already in that state, then confirms the change |
| `fill(value)`                 | focuses a field, selects its contents and inserts the value; `""` empties it |
| `clear()`                     | empties a field                                                            |
| `press(key)`                  | focuses the element and presses a key                                      |
| `pressSequentially(text)`     | focuses the element and types the text key by key                         |
| `selectOption(choice)`        | chooses a `<select>`'s option by `value`, `label` or `index`                |
| `setInputFiles(files)`        | sets a file input's files                                                  |
| `dragTo(target)`              | presses on the element, moves to the target with the button held, releases |
| `focus()`, `scrollIntoView()` | focuses it, or scrolls it into view                                        |

An action sends its input at most once. If it fails after the input may have reached the page, the error says so.

## Checks

Before sending anything, an action waits, checking at each animation frame, until its element is ready:

| Action                                                            | Checks                                                                   |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `click`, `dblclick`, `tap`, `check`, `uncheck`, `dragTo`, `hover` | visible, stable, enabled, not inert, in the viewport, receives the pointer |
| `fill`, `clear`                                                   | visible, enabled, editable, not inert                                    |
| `focus`, `press`, `pressSequentially`                             | visible, not inert                                                       |
| `scrollIntoView`                                                  | visible, stable                                                          |
| `selectOption`                                                    | visible, enabled                                                         |
| `setInputFiles`                                                   | none                                                                     |

- "Stable": stopped moving. "In the viewport": scrolled there. "Receives the pointer": nothing covers the point.
- After the checks pass, it checks once more and sends. If something covers a click's target in between, the page
  never sees the click, and the action checks again.
- A timeout names the last failed check: `Another element covers the element's action point: div.toast "Saved"`.

Turn single checks off with `checks`; there's no blanket `force`. `trial: true` runs the checks and sends nothing:

```ts
import { Page } from "@usestrider/browser"

declare const page: Page.Page

const close = page.getByRole("button", { name: "Close" })
const behindOverlay = close.click({ checks: { receivesPointer: false } })
const dryRun = page.getByRole("button", { name: "Delete" }).click({ trial: true })
```

## Typing

- `fill` inserts text as pasting would: the page sees input events, not key presses. A date, color or range input
  has its value set, and a value it refuses fails with `InvalidInput`.
- `pressSequentially` sends a key per character, for fields that react to each keystroke. `delay` spaces them.
- Pass secrets as `Redacted`. The value is typed, and never appears in errors, spans, logs or traces:

```ts
import { Page } from "@usestrider/browser"
import { Config, Effect } from "effect"

const logIn = Effect.fn("logIn")(function*(page: Page.Page) {
  yield* page.getByLabel("Email").fill("ada@example.com")
  yield* page.getByLabel("Password").fill(yield* Config.Redacted("APP_PASSWORD"))
  yield* page.getByRole("button", { name: "Sign in" }).click()
})
```

## Keys

Keys use UI Events names, as in `event.key`: `"Enter"`, `"Tab"`, `"ArrowDown"`, `"a"`. Modifiers are an option;
there's no `"Control+A"`:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const copyAll = Effect.fn("copyAll")(function*(page: Page.Page) {
  const editor = page.getByRole("textbox", { name: "Notes" })
  yield* editor.press("a", { modifiers: ["Control"] })
  yield* editor.press("c", { modifiers: ["Control"] })
  yield* editor.press("Enter")
})
```

Typing uses a US layout unless the context sets another: `Browser.newPage({ keyboardLayout: "de" })`, with Shift,
AltGr and dead keys. Layouts: `us`, `uk`, `de`, `fr`, `es`, `it`. Firefox sends only the keys' values; WebKit has no
layouts.

## Files

`setInputFiles` takes `FileInput`s:

```ts
import { FileInput, Page } from "@usestrider/browser"
import { Effect } from "effect"

const upload = Effect.fn("upload")(function*(page: Page.Page, csv: string) {
  yield* page.getByLabel("Avatar").setInputFiles(FileInput.local("./avatar.png"))
  yield* page.getByLabel("Report").setInputFiles(
    FileInput.bytes("report.csv", "text/csv", new TextEncoder().encode(csv))
  )
})
```

- `FileInput.local` names a file on this machine.
- `FileInput.bytes` makes the file in the page, so it works with a browser on another machine.
- An upload through a file chooser, not an input, is answered with `FileChooser.handle`
  ([Events](/docs/events/events#dialogs)).

## Dragging

`dragTo` drags with the pointer. A native HTML drag (`draggable="true"`) finishes only on Chromium;
`html: "synthetic"` has the page dispatch the drag's events instead, on every browser, untrusted:

```ts
import { Page } from "@usestrider/browser"

declare const page: Page.Page

const card = page.getByRole("listitem").filter({ hasText: "Write the guide" })
const done = page.getByRole("list", { name: "Done" })
const moved = card.dragTo(done, { html: "synthetic" })
```

## The keyboard and the mouse

`page.keyboard` types into whatever has focus; `page.mouse` acts at coordinates, for canvases and maps. Neither
checks anything. Holding a key or button is scoped, so a failed step never leaves it held:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const selectRange = Effect.fn("selectRange")(function*(page: Page.Page) {
  yield* page.getByRole("option", { name: "Apples" }).click()
  yield* Effect.scoped(Effect.gen(function*() {
    yield* page.keyboard.hold("Shift")
    yield* page.getByRole("option", { name: "Pears" }).click()
  }))
})

const sketch = Effect.fn("sketch")(function*(page: Page.Page) {
  yield* page.mouse.move({ x: 100, y: 100 })
  yield* Effect.scoped(Effect.gen(function*() {
    yield* page.mouse.hold("left")
    yield* page.mouse.move({ x: 220, y: 140 }, { steps: 12 })
  }))
  yield* page.mouse.wheel({ x: 0, y: 400 })
})
```

A click while Shift is held is a Shift-click; moves while a button is held are a drag. Input to one page goes one
gesture at a time.

## Browser differences

- Native HTML drag and drop: Chromium only.
- `tap` and touch: not on WebKit.
- Keyboard layouts: partial on Firefox, none on WebKit.

Each fails with `Unsupported`, naming the capability, before anything is sent.
