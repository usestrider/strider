## Two ways to ask

There are two ways to find out about a page, and they behave differently on purpose:

- **An expectation** (`Expect.to*`) waits for something to become true, checking again each time the page
  changes, until it is or the deadline passes.
- **A read** (`readText`, `count`, `isVisible`, `page.title`) says what is true now. It never waits and never
  retries.

When the program's next step depends on the page reaching a state, expect it. When you want a value to use, read
it, after expecting whatever the value depends on.

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const cartTotal = Effect.fn("cartTotal")(function*(page: Page.Page) {
  const total = page.getByTestId("cart-total")
  yield* total.pipe(Expect.toHaveText(/^\$\d+\.\d{2}$/)) // wait for a price
  return yield* total.readText // then read it
})
```

## Expectations

| Matcher                                        | Passes when                                                      |
| ---------------------------------------------- | ---------------------------------------------------------------- |
| `toBeVisible`, `toBeHidden`                    | exactly one element matches and is visible; or none is, or it's hidden |
| `toBeEnabled`, `toBeDisabled`                  | the element is enabled, or disabled                              |
| `toBeChecked`, `toBeFocused`, `toBeEditable`   | it's checked; it has focus, through open shadow roots; it's editable |
| `toHaveText(expected)`                         | its text is `expected`, or for a list, each match's in order      |
| `toContainText(expected)`                      | its text contains `expected`                                     |
| `toHaveValue(expected)`                        | a form control's value is `expected`                             |
| `toHaveAttribute(name, expected?)`             | it has the attribute, with that value if given                   |
| `toHaveCount(n)`                               | exactly `n` elements match                                       |
| `toMatchAria(pattern)`                         | its accessibility tree matches a pattern                         |
| `toHaveURL(expected)`, `toHaveTitle(expected)` | the page's URL or title matches                                  |

With a string, `toHaveText` matches the whole text exactly, and with a `RegExp` it tests it. `toBeHidden` passes
when nothing matches at all, so it's also how to wait for something to go away.

Matchers with no arguments are themselves the function, and those with arguments are dual, as Effect's own
functions are. These lines are the same:

```ts
import { Expect, Page } from "@usestrider/browser"

declare const page: Page.Page

const badge = page.getByTestId("cart-count")
const piped = badge.pipe(Expect.toHaveText("3"))
const direct = Expect.toHaveText(badge, "3")
const visible = badge.pipe(Expect.toBeVisible)
```

## How expectations wait

A locator's expectation waits in the page. It checks, and if the condition doesn't hold, checks again on each
change to the document, each input or focus event, and each animation frame, until it does or a second has
passed, and then Strider asks again, until the deadline. No change is missed between checks, and there is no
polling interval to tune and no backoff, which would make a test slower the longer it waits.

An expectation on the page's URL is checked again each time the URL changes. Everything runs on the real clock,
within the operation's deadline.

## Expecting anything

`Expect.that` takes any subject and a `Condition`, a predicate with a description that appears in the failure:

```ts
import { Condition, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const atLeast = (n: number) =>
  Condition.make<number>(`at least ${n}`, (count) => count >= n)

const resultsLoaded = Effect.fn("resultsLoaded")(function*(page: Page.Page) {
  yield* Expect.that(page.getByRole("listitem").count, atLeast(10))
  const onPage2 = Condition.make("on page 2", (url: string) => url.includes("page=2"))
  yield* Expect.that(page.url, onPage2)
})
```

A subject Strider keeps up to date, such as `page.url`, is checked again each time it changes. Any other
effect is run again every 100 ms, which `Expect.withCheckInterval` changes. `Condition.not`, `Condition.and` and
`Condition.because` combine conditions and explain them.

## Structure

`toMatchAria` matches an element's accessibility tree against a pattern. How a node's children are compared is
always stated: `exactly` these children and no others, `including` these in this order with others allowed
between, or `unchecked`:

```ts
import { AriaPattern, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const link = (name: string) => AriaPattern.node("link", name, AriaPattern.unchecked)
const links = AriaPattern.including(link("Orders"), link("Account"))
const mainNav = AriaPattern.node("navigation", "Main", links)

const mainNavigation = Effect.fn("mainNavigation")(function*(page: Page.Page) {
  yield* page.getByRole("navigation").pipe(Expect.toMatchAria(mainNav))
})
```

## Reads

| Read                                  | Gives                                                            |
| ------------------------------------- | ---------------------------------------------------------------- |
| `readText`                            | the element's text: the text `getByText` matches                 |
| `readValue`                           | a form control's value                                           |
| `readAttribute(name)`                 | an attribute, as an `Option`                                     |
| `readHtml`                            | the element's `outerHTML`                                        |
| `isVisible`, `isEnabled`, `isChecked` | what they say, now                                               |
| `count`, `all`                        | how many elements match, and a locator for each                  |
| `page.title`, `page.readHtml`         | the document's title, and its HTML                               |

Reads are strict, like actions: they need exactly one match. Several fail with `StrictViolation`, and none fails at
once with `NoMatch`, since a read doesn't wait for an element to arrive. `count` and `all` take any number.

A read that fails with `NoMatch` because the element hasn't rendered yet is the most common mistake. The fix is to
expect what you're waiting for, then read:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect, Option } from "effect"

const orderNumber = Effect.fn("orderNumber")(function*(page: Page.Page) {
  const confirmation = page.getByRole("status")
  yield* confirmation.pipe(Expect.toContainText("Order"))
  const id = yield* confirmation.readAttribute("data-order-id")
  return Option.getOrElse(id, () => "unknown")
})
```

## Several checks, every failure

An expectation fails the effect it's in, so the first failure stops the rest. To check several things and see
every failure, collect them with Effect, which already knows how:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const summary = Effect.fn("summary")(function*(page: Page.Page) {
  return yield* Effect.all([
    page.getByTestId("subtotal").pipe(Expect.toHaveText("$40.00")),
    page.getByTestId("shipping").pipe(Expect.toHaveText("$5.00")),
    page.getByTestId("total").pipe(Expect.toHaveText("$45.00"))
  ], { mode: "result" })
})
```

## State that changes

Some of a page's state is watchable: its status, its URL and its frame tree, a download's progress, a browser's
pages. A `Watchable` is an `Effect` that reads the current value, with `changes`, a stream that starts with the
current value, and `waitFor`, which waits until the value satisfies a predicate:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const fullyLoaded = Effect.fn("fullyLoaded")(function*(page: Page.Page) {
  const url = yield* page.url
  yield* page.status.waitFor((status) =>
    status._tag === "Open" && status.document.readiness === "complete"
  )
  return url
})
```

`waitFor` checks the current value first, so it can't miss a state that's already true.
It fails with `Watchable.Ended` when the value has settled for good on one that doesn't satisfy it, such as waiting
for a page to load after it closed.

## Evaluating in the page

For what no query or read covers, run a function in the page. `page.evaluate` runs it in an isolated world of
Strider's, which sees the page's DOM but not its scripts' globals; `evaluateInMainWorld` runs it among the page's
own scripts, and needs a `Page` you control:

```ts
import { Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"

const Dimensions = Schema.Struct({ width: Schema.Number, height: Schema.Number })

const viewport = Effect.fn("viewport")(function*(page: Page.Page) {
  const size = yield* page.evaluate(() => ({ width: innerWidth, height: innerHeight }))
  const version = yield* page.evaluateInMainWorld(() =>
    (globalThis as { appVersion?: string }).appVersion
  )
  return { size: yield* Schema.decodeUnknownEffect(Dimensions)(size), version }
})
```

The function crosses into the page, so it must be self-contained: values it needs go in as arguments,
`page.evaluate((id) => document.getElementById(id)?.textContent, "total")`. Its result comes back by value, and its
type says what actually arrives. A DOM node can't come back by value; `evaluateHandle` gives a handle to it instead,
released when its scope closes.
