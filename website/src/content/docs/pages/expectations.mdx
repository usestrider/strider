A check that reads the page once can run before the page catches up, and pass or fail by timing. An expectation
waits until the page is right, so a read after it gets the value you meant.

## Expectations before reads

- **An expectation** (`Expect.to*`) retries on each change to the page until it passes or the deadline does.
- **A read** (`readText`, `count`, `isChecked`, [`page.title`](/docs/first-program#reads)) says what's true now. It never waits or retries.

Expect the state you need, then read the value:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const cartTotal = Effect.fn("cartTotal")(function*(page: Page.Page) {
  const total = page.getByTestId("cart-total")
  yield* total.pipe(Expect.toHaveText(/^\$\d+\.\d{2}$/)) // wait for a price
  return yield* total.readText // then read it
})
```

## The matchers

Each matcher takes a locator, except `toHaveURL` and `toHaveTitle`, which take the page:

| Matcher                                        | Passes when                                                      |
| ---------------------------------------------- | ---------------------------------------------------------------- |
| `toBeVisible`, `toBeHidden`                    | exactly one element matches and is visible; or no match is visible, however many match |
| `toBeEnabled`, `toBeDisabled`                  | the element is enabled, or disabled                              |
| `toBeChecked`, `toBeFocused`, `toBeEditable`   | it's checked; it has focus, through open shadow roots; it's editable |
| `toHaveText(expected)`                         | its text is `expected`, or for a list, each match's in order      |
| `toHaveClass(expected)` | its full class string matches, or for a list, each element’s in order |
| `toContainText(expected)`                      | its text contains `expected`                                     |
| `toHaveAccessibleName(expected, options?)` | its accessible name matches; `ignoreCase` overrides regex flags |
| `toHaveValue(expected)`                        | a form control's value is `expected`                             |
| `toHaveValues(expected)` | one multiple select has the selected values in option order |
| `toHaveAttribute(name, expected?)`             | it has the attribute, with that value if given                   |
| `toHaveCSS(name, expected, options?)`          | its computed CSS property matches an exact string or regular expression |
| `toHaveCount(n)`                               | exactly `n` elements match                                       |
| `toMatchAria(pattern)`                         | its accessibility tree matches a pattern                         |
| `toHaveURL(expected)`, `toHaveTitle(expected)` | the page's URL or title matches                                  |

An element with `opacity: 0` on itself or any ancestor counts as hidden: `toBeVisible` waits for it to
become visible, and `toBeHidden` passes. Actions can accept transparent elements; see [action checks](/docs/pages/actions#checks).

Class strings preserve spacing and class order. Missing class attributes count as empty strings; an array also checks the number of matches. Scalar checks retry until exactly one element matches.

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const checkClasses = Effect.fn("checkClasses")(function*(page: Page.ReadonlyPage) {
  yield* page.getByTestId("status").pipe(Expect.toHaveClass("status ready"))
  yield* page.getByRole("listitem").pipe(Expect.toHaveClass(["selected", /^pending/]))
})
```

Selected values match exactly, including whitespace, or by regular expression, in option order.
`toHaveValues([])` waits for an empty selection; the locator must still match one `<select multiple>`.
Labels resolve to their associated control. Other controls fail with expectation evidence at the deadline.

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const checkColors = Effect.fn("checkColors")(function*(page: Page.ReadonlyPage) {
  yield* page.getByLabel("Colors").pipe(Expect.toHaveValues(["red", /^green$/]))
})
```

A string `toHaveText` matches the whole text; a `RegExp` is tested; an array matches each match's text, in order.
`toBeHidden` also passes when nothing matches, so it waits for something to go away:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const searchHerons = Effect.fn("searchHerons")(function*(page: Page.Page) {
  yield* page.getByRole("searchbox").fill("heron")
  yield* page.getByRole("searchbox").press("Enter")
  yield* page.getByRole("progressbar").pipe(Expect.toBeHidden)
  const results = page.getByRole("list", { name: "Results" }).getByRole("listitem")
  yield* results.pipe(Expect.toHaveText(["Grey heron", /^Great blue heron/]))
  yield* page.pipe(Expect.toHaveTitle(/heron/))
  yield* page.pipe(Expect.toHaveURL(/[?&]q=heron/))
})
```

Use an accessible-name expectation to check what assistive technology calls a control, including names from labels
and ARIA references. Strings match the whole name with whitespace normalized; `ignoreCase` overrides a regular
expression's case flag. A hidden element has an empty name, while a hidden label can still name a visible control.
Roles that prohibit naming, such as generic, paragraph and code, have an empty name even with an ARIA label.
Their content can still name another element, and an explicit nameable role overrides the implicit role. Role
locators use this same name computation. Missing or multiple matches retry until the deadline and report their
count on failure.

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const saveName = Effect.fn("saveName")(function*(page: Page.ReadonlyPage) {
  yield* page.getByTestId("save").pipe(Expect.toHaveAccessibleName("Save changes"))
  yield* Expect.toHaveAccessibleName(page.getByTestId("save"), /save/, {
    ignoreCase: true
  })
})
```

Computed CSS includes styles from stylesheets and inheritance, in the browser's serialized form.
Strings compare exactly, including whitespace; regular expressions keep their flags:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const styled = Effect.fn("styled")(function*(page: Page.ReadonlyPage) {
  const notice = page.getByRole("status")
  yield* notice.pipe(Expect.toHaveCSS("display", "flex"))
  yield* Expect.toHaveCSS(notice, "color", /^rgb\(/)
  yield* notice.pipe(Expect.toHaveCSS("display", "none", { not: true }))
  yield* notice.pipe(Expect.toHaveCSS("content", "\"Ready\"", { pseudo: "before" }))
})
```

CSS expectations require exactly one match even with `not: true`. Missing or multiple matches retry until
the deadline and report the match count; Playwright rejects multiple matches immediately.
Use `Deadline.within` to bound the expectation. Without options, it compares the element's own computed style.

A matcher without arguments is the function itself; one with arguments is dual:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const cartSurvivesReload = Effect.fn("cartSurvivesReload")(function*(page: Page.Page) {
  const badge = page.getByTestId("cart-count")
  const piped = badge.pipe(Expect.toHaveText("3"))
  const direct = Expect.toHaveText(badge, "3")
  const visible = badge.pipe(Expect.toBeVisible)
  yield* visible
  yield* piped
  yield* page.reload()
  yield* direct
})
```

A locator's expectation re-checks in the page on each DOM change, `input`, `change` or focus event and animation
frame, in rounds of up to a second, until the deadline. Nothing is missed between checks; there's no polling
interval or backoff.

The first failed expectation stops the rest. To see every failure, collect them with Effect:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const summary = Effect.fn("summary")(function*(page: Page.Page) {
  return yield* Effect.all([
    page.getByTestId("subtotal").pipe(Expect.toHaveText("$40.00")),
    page.getByTestId("shipping").pipe(Expect.toHaveText("$5.00")),
    page.getByTestId("total").pipe(Expect.toHaveText("$45.00"))
  ], { mode: "result" })
})
```

## Expecting anything

When no matcher fits, such as a count of at least ten, expect any effect to meet a condition. `Expect.that` takes
an effect and a `Condition`, a predicate whose description the failure shows. `Condition.and` and `Condition.not`
combine conditions, and `Condition.because` says why in the failure:

```ts
import { Condition, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const atLeast = (n: number) =>
  Condition.make<number>(`at least ${n}`, (count) => count >= n)

const onePage = Condition.and(atLeast(10), Condition.not(atLeast(21))).pipe(
  Condition.because("a page shows 10 to 20 results")
)

const resultsLoaded = Effect.fn("resultsLoaded")(function*(page: Page.Page) {
  const results = page.getByRole("listitem").count
  yield* Expect.that(results, onePage).pipe(Expect.withCheckInterval("250 millis"))
})
```

A [`Watchable`](#watchables) such as `page.url` re-checks on each change; any other effect re-runs every
100 ms, or as `Expect.withCheckInterval` sets.

## Accessibility trees

Expecting each element alone can't check their order, or that nothing else is there. `toMatchAria` matches a
region's accessibility tree, its roles, names and order, against a pattern in one expectation. Each node says how
its children compare: `exactly`, `including` (in order, others allowed between) or `unchecked`:

```ts
import { AriaPattern, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const link = (name: string) => AriaPattern.node("link", name, AriaPattern.unchecked)
const links = AriaPattern.including(link("Orders"), link("Account"))
const mainNav = AriaPattern.node("navigation", "Main", links)

const tab = (name: string) => AriaPattern.node("tab", name, AriaPattern.unchecked)
const productTabs = AriaPattern.node(
  "tablist",
  "Product",
  AriaPattern.exactly(tab("Details"), tab("Reviews"))
)

const productPage = Effect.fn("productPage")(function*(page: Page.Page) {
  yield* page.getByRole("navigation").pipe(Expect.toMatchAria(mainNav))
  yield* page.getByRole("tablist").pipe(Expect.toMatchAria(productTabs))
})
```

## Reads

| Read                                  | Gives                                                            |
| ------------------------------------- | ---------------------------------------------------------------- |
| `readText`                            | the element's text: the text [`getByText`](/docs/pages/locators#matching-text) matches |
| `readValue`                           | a form control's value                                           |
| `readAttribute(name)`                 | an attribute, as an `Option`                                     |
| `readHtml`                            | the element's `outerHTML`                                        |
| `isVisible`, `isEnabled`, `isEditable`, `isChecked` | what they say, now                                               |
| `count`, `all`                        | how many elements match, and a locator for each                  |
| `page.title`, `page.readHtml`         | the document's title, and its HTML                               |

`isEditable` reads the same state as `toBeEditable`: a text or settable input, textarea or
contenteditable element must be enabled and not read-only. Hidden or inert elements can still read true.
Other kinds, including selects and ARIA-only textboxes, read false; Playwright accepts more kinds and
throws for unsupported elements. Native read-only state and the element's `aria-readonly="true"` prevent
editing; ARIA tokens are case-sensitive. Contenteditable follows the browser’s `isContentEditable`
property; WebKit can report false for hidden or inert contenteditable elements.

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const canRename = Effect.fn("canRename")(function*(page: Page.ReadonlyPage) {
  return yield* page.getByRole("textbox", { name: "Name" }).isEditable
})
```

Reads need [exactly one match](/docs/errors#strictness); one that hasn't rendered yet fails with `NoMatch`, so
expect it first. `count` and `all` take any number, so count what may not be there:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect, Option } from "effect"

const savedSettings = Effect.fn("savedSettings")(function*(page: Page.Page) {
  const form = page.getByRole("form", { name: "Settings" })
  yield* form.pipe(Expect.toBeVisible)
  const name = yield* form.getByLabel("Display name").readValue
  const newsletter = yield* form.getByLabel("Send me the newsletter").isChecked
  const avatar = yield* form.getByRole("img", { name: "Avatar" }).readAttribute("src")
  const warnings = yield* page.getByRole("alert").count
  return {
    name,
    newsletter,
    avatar: Option.getOrElse(avatar, () => "none"),
    warned: warnings > 0
  }
})
```

## Watchables

A URL read once misses the redirect after it. A page's status, URL and frames, a download's progress and a
browser's pages are `Watchable`s, which read the value now, stream its `changes`, or wait for one with `waitFor`:

```ts
import { Page } from "@usestrider/browser"
import { Effect, Stream } from "effect"

const signIn = Effect.fn("signIn")(function*(page: Page.Page) {
  yield* page.url.changes.pipe(
    Stream.runForEach((url) => Effect.log(`At ${url}`)),
    Effect.forkScoped
  )
  yield* page.getByRole("button", { name: "Sign in" }).click()
  return yield* page.url.waitFor((url) => new URL(url).pathname === "/dashboard")
})
```

- `changes` gives the current value, then the latest each time the consumer takes one, so a slow consumer sees the
  newest value, not every one.
- Use `waitFor` to go on once a state comes, such as the dashboard's URL; use `Expect.that` when the state not
  coming is a failure, so the error says what was expected and what was seen.
- `waitFor` checks the current value first, so wait for what the click changes: a wait for the load would pass at
  once, on the sign-in page, which has already loaded.
- It fails with `Watchable.Ended` when the value settles on one that doesn't match, such as a completed download's
  status, and with `TargetGone` when what it watches ends, such as a closed page.

## Evaluating in the page

When no read gives what you need, such as the viewport's size or a global the app sets, run a function in the page.
`page.evaluate` runs a function in an isolated world, which sees the DOM but not the page's globals.
`evaluateInMainWorld` runs it among the page's scripts, and needs
[control](/docs/pages/attaching#access-levels), which a `Page` you opened has. On WebKit, which has no isolated
worlds, `page.evaluate` fails with `Unsupported`, so use `evaluateInMainWorld` there:

```ts
import { Page } from "@usestrider/browser"
import { Effect, Schema } from "effect"

const Dimensions = Schema.Struct({ width: Schema.Number, height: Schema.Number })

const viewport = Effect.fn("viewport")(function*(page: Page.Page) {
  const size = yield* page.evaluate(() => ({ width: innerWidth, height: innerHeight }))
  const version = yield* page.evaluateInMainWorld(() =>
    (globalThis as { appVersion?: string }).appVersion
  )
  return { size: yield* Schema.decodeUnknownEffect(Dimensions)(size), version }
})
```

- The function must be self-contained; pass values as arguments:
  `page.evaluate((id) => document.getElementById(id)?.textContent, "total")`.
- The result comes back by value, typed as what arrives.
- A DOM node can't come back by value: [`evaluateHandle`](/docs/api/browser/Page#Page.evaluateHandle) gives a
  handle, released with its scope.

To read every locator match together, use `evaluateAll`. It passes an empty array when nothing matches:

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const names = Effect.fn("names")(function*(page: Page.ReadonlyPage) {
  return yield* page.getByRole("listitem").evaluateAll((items) =>
    items.map((item) => item.textContent)
  )
})
```

Membership is resolved once before the callback is dispatched, without waiting for matches. The elements remain
live: they may change or detach before the callback runs. Synchronous callback code runs in one JavaScript turn;
changes can occur across an async callback's awaits. The promise is awaited within the operation's deadline, but
a timeout cannot stop code already running in the page. Arguments and results cross by value as with `evaluate`;
no array handle is retained. This needs inspect access and isolated-world support; stock WebKit refuses it with
`Unsupported`.
