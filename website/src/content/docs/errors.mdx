A failure that says only that something went wrong leaves you rerunning the program to find out why. Each of
Strider's says what happened, why and what to do, and is in the operation's type, so you can recover from the ones
you expect.

## Three kinds of failure

| Error                  | Means                                                         | Carries                                 |
| ---------------------- | ------------------------------------------------------------- | --------------------------------------- |
| the module's own error | the operation couldn't do what it was asked                    | a `reason`, a class with its own fields |
| `TargetGone`           | something it needed ended: the page closed, the frame detached | `reason`: why it ended                  |
| `Timeout`              | the [deadline](/docs/deadlines) passed                         | `phase`: [how far it got](/docs/deadlines#timeouts) |

Each module has one error: `LocatorError` for a click, `PageError` for a navigation, `DownloadError`,
`ExpectationFailed`. Every reason has a `hint`, and the message includes it:

```
click page.getByRole("button", { name: "Save" }): 2 matches (2 elements match and 1 of them is visible; add .filter({ visible: true }))
```

Some reasons belong to one module, such as `Locator.StrictViolation`. These are shared, in `Reason`:

- `InvalidInput`: an argument the operation can't use, such as a malformed selector. Fails at once.
- `Unsupported`: this backend can't do it. The reason names the capability.
- `NotPermitted`: you don't have the access it needs, such as acting on a page you may only inspect.
- `BackendFailure`: the browser refused or broke; its error is the `cause`.

## Recovering

`Effect.catchReason` matches a module's error and one of its reasons:

```ts
import { Locator, Page } from "@usestrider/browser"
import { Console, Effect } from "effect"

const listSuggestions = (violation: Locator.StrictViolation) =>
  Console.log("Several banners:", violation.suggestions)

const dismissBanner = Effect.fn("dismissBanner")(function*(page: Page.Page) {
  const accept = page.getByRole("button", { name: "Accept cookies" })
  yield* accept.click().pipe(
    Effect.catchReason("LocatorError", "StrictViolation", listSuggestions)
  )
})
```

A shared reason is the same class in every module: `Effect.catchReason(tag, "Unsupported", …)` works for any tag.

## Strict by default

An action or read needs exactly one element. Two or more fail at once with `StrictViolation`, which lists them and
suggests `.filter({ visible: true })` when only one is visible. Ambiguity doesn't wait: it's a bug in the locator.

When duplicates are brief, such as overlapping toasts, wait for them to settle first:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const dismissToast = Effect.fn("dismissToast")(function*(page: Page.Page) {
  const toasts = page.getByRole("status")
  yield* toasts.pipe(Expect.toHaveCount(1))
  yield* toasts.getByRole("button", { name: "Dismiss" }).click()
})
```

## Failed expectations

`ExpectationFailed` has what was expected, the last value seen and every value seen. When the locator matched
nothing, `nearest` shows the page where the locator stopped matching, and `suggestions` are locators for elements
with similar names.

## Diagnostics

Every failure carries `diagnostics`: the operation's id; for an action, whether its input may have reached the
page, `dispatch`: `NotSent`, `MayHaveBeenSent` or `Acknowledged`; and, for an [operation with steps](/docs/deadlines#operations-of-your-own), `progress`.

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const mayHavePaid = Effect.fn("mayHavePaid")(function*(page: Page.Page) {
  return yield* page.getByRole("button", { name: "Pay" }).click().pipe(
    Effect.as(true),
    Effect.catchTag(
      "LocatorError",
      (error) => Effect.succeed(error.diagnostics.dispatch._tag === "MayHaveBeenSent")
    )
  )
})
```

- Errors are Schemas, so they encode as data; the `strider` command and the agent toolkit return them that way.
- Secrets never appear: `Redacted` values, cookies and typed passwords are left out of messages, spans and logs.
- Under the default preset, `strict`, a URL keeps its origin and path with query values redacted.
  `Diagnostics.withPreset("local")` shows URLs whole.
