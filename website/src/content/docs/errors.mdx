## Three kinds of failure

| Error                  | Means                                                         | Carries                                 |
| ---------------------- | ------------------------------------------------------------- | --------------------------------------- |
| the module's own error | the operation couldn't do what it was asked                    | a `reason`, a class with its own fields |
| `TargetGone`           | something it needed ended: the page closed, the frame detached | `reason`: why it ended                  |
| `Timeout`              | the deadline passed                                            | `phase`: how far it got                 |

Each module has one error: `LocatorError` for a click, `PageError` for a navigation, `DownloadError`,
`ExpectationFailed`. Every reason has a `hint`, and the message includes it:

```
click page.getByRole("button", { name: "Save" }): 2 matches (2 elements match and 1 of them is visible; add .filter({ visible: true }))
```

Some reasons belong to one module, such as `Locator.StrictViolation`. These are shared, in `Reason`:

- `InvalidInput`: an argument the operation can't use, such as a malformed selector. Fails at once.
- `Unsupported`: this backend can't do it. The reason names the capability.
- `NotPermitted`: you don't have the access it needs, such as acting on a page you may only inspect.
- `BackendFailure`: the browser refused or broke; its error is the `cause`.

## Recovering

`Effect.catchReason` matches a module's error and one of its reasons:

```ts
import { Locator, Page } from "@usestrider/browser"
import { Console, Effect } from "effect"

const listSuggestions = (violation: Locator.StrictViolation) =>
  Console.log("Several banners:", violation.suggestions)

const dismissBanner = Effect.fn("dismissBanner")(function*(page: Page.Page) {
  const accept = page.getByRole("button", { name: "Accept cookies" })
  yield* accept.click().pipe(
    Effect.catchReason("LocatorError", "StrictViolation", listSuggestions)
  )
})
```

A shared reason is the same class in every module: `Effect.catchReason(tag, "Unsupported", …)` works for any tag.

## Strict by default

An action or read needs exactly one element. Two or more fail at once with `StrictViolation`, which lists them and
suggests `.filter({ visible: true })` when only one is visible. Ambiguity doesn't wait: it's a bug in the locator.

When duplicates are brief, such as overlapping toasts, wait for them to settle first:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const dismissToast = Effect.fn("dismissToast")(function*(page: Page.Page) {
  const toasts = page.getByRole("status")
  yield* toasts.pipe(Expect.toHaveCount(1))
  yield* toasts.getByRole("button", { name: "Dismiss" }).click()
})
```

## Deadlines

An operation has one deadline for everything it does, from waiting its turn at the page's input to confirming the
result. Without one around it, it gets the default budget, 30 seconds.

`Deadline.within` sets one deadline for everything inside, shared rather than per step:

```ts
import { Deadline, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const pay = Effect.fn("pay")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Pay" }).click()
  yield* page.getByText("Payment received").pipe(Expect.toBeVisible)
}, Deadline.within("5 seconds"))
```

- A nested deadline can only be shorter.
- `Deadline.withDefaultBudget("1 minute")` changes the default for a program.
- `Deadline.remaining` reads the time left.
- A real browser's deadlines run on the real clock, even under `TestClock`; `Browser.layerTest`'s on Effect's.

## Timeouts

A `Timeout`'s `phase` says how far the operation got:

| Phase                   | The operation                                                              |
| ----------------------- | -------------------------------------------------------------------------- |
| `resolving`             | never found a matching element                                              |
| `waitingForCondition`   | found it, but it never became ready: hidden, disabled, covered, moving      |
| `dispatchedUnconfirmed` | sent the input, but couldn't confirm the result                             |
| `postcondition`         | acted, and what should follow never did, such as a navigation committing    |
| `waitingForEvent`       | waited for an event, such as a popup, that never came                       |

Before `dispatchedUnconfirmed`, nothing reached the page and retrying is safe. After it, check the page first:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const submitOnce = Effect.fn("submitOnce")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Submit" }).click().pipe(
    Effect.catchTag("Timeout", (timeout) =>
      Effect.gen(function*() {
        if (timeout.phase !== "dispatchedUnconfirmed") {
          return yield* Effect.fail(timeout)
        }
        yield* page.getByText("Submitted").pipe(Expect.toBeVisible)
      }))
  )
})
```

Strider never retries input that may have reached the page. It retries only a gesture it stopped before the page
saw it, such as a click that would have hit a toast.

## Operations of your own

`Operation.fn` is `Effect.fn` for an operation: the caller of your helper gets one deadline for all of it, and a
`Timeout` named for it that says how far it got.

```ts
import { Deadline, Operation, Page } from "@usestrider/browser"
import { Effect } from "effect"

const checkout = Operation.fn("checkout")(
  function*(page: Page.Page, confirmed: Effect.Effect<string>) {
    yield* page.getByLabel("Card number").fill("4242 4242 4242 4242")
    yield* page.getByRole("button", { name: "Pay" }).click()
    return yield* Operation.bound(confirmed)
  },
  Deadline.within("20 seconds")
)
```

- Each operation inside is a step. If the click runs out of time, the caller gets `checkout`'s `Timeout`, in the
  click's phase, and `diagnostics.progress` lists `Locator.fill` as `ok`.
- Inside the body, a step's `Timeout` is still the step's: catching one around the click catches the click's.
- `Operation.bound` ends a wait of your own at the deadline. Past it, this `Timeout` is in the phase
  `postcondition`: the click went out, and the confirmation didn't come.
- `Operation.markSent` notes a side effect of your own, such as a call to your API, and `Operation.observe` notes
  why the operation isn't done yet. They compile only inside an operation.
- `Operation.named("cartCount")` makes an effect an operation, as `Effect.withSpan` makes it a span.

## Failed expectations

`ExpectationFailed` has what was expected, the last value seen and every value seen. When the locator matched
nothing, `nearest` shows the page where the locator stopped matching, and `suggestions` are locators for elements
with similar names.

## Diagnostics

Every failure carries `diagnostics`: the operation's id; for an action, whether its input may have reached the
page, `dispatch`: `NotSent`, `MayHaveBeenSent` or `Acknowledged`; and, for an operation with steps, `progress`.

```ts
import { Page } from "@usestrider/browser"
import { Effect } from "effect"

const mayHavePaid = Effect.fn("mayHavePaid")(function*(page: Page.Page) {
  return yield* page.getByRole("button", { name: "Pay" }).click().pipe(
    Effect.as(true),
    Effect.catchTag(
      "LocatorError",
      (error) => Effect.succeed(error.diagnostics.dispatch._tag === "MayHaveBeenSent")
    )
  )
})
```

- Errors are Schemas, so they encode as data; the `strider` command and the agent toolkit return them that way.
- Secrets never appear: `Redacted` values, cookies and typed passwords are left out of messages, spans and logs.
- Under the default preset, `strict`, a URL keeps its origin and path with query values redacted.
  `Diagnostics.withPreset("local")` shows URLs whole.
