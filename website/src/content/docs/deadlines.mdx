A wait for something that never happens would hang a program, and a limit on each step would add up to more than
you meant. So each operation has one deadline, and a `Timeout` that says how far it got.

## Setting a deadline

An operation is one call of Strider's, such as a click, a navigation or an expectation; one that runs inside
another is a step of it. An operation has one deadline for everything it does, from waiting its turn at the page's
input to confirming the result. Without one around it, it gets the default budget, 30 seconds.

`Deadline.within` sets one deadline for everything inside, shared rather than per step:

```ts
import { Deadline, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const pay = Effect.fn("pay")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Pay" }).click()
  yield* page.getByText("Payment received").pipe(Expect.toBeVisible)
}, Deadline.within("5 seconds"))
```

- Every command an operation sends waits for its reply until the deadline, a cookie read or adding a
  [route](/docs/events/routes) as much as a click.
- A nested deadline can only be shorter.
- A real browser's deadlines run on the real clock, even under `TestClock`;
  [`Browser.layerTest`](/docs/tools/testing)'s on Effect's.

When several steps can each take longer than 30 seconds, `Deadline.withDefaultBudget` raises the default rather
than sharing one total: each operation inside gets the whole budget from when it starts. A deadline from `within`
still wins:

```ts
import { Deadline, Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const nightlyReport = Effect.fn("nightlyReport")(function*(page: Page.Page) {
  yield* page.goto("https://app.example.com/reports/nightly")
  yield* page.getByRole("button", { name: "Generate" }).click()
  yield* page.getByText("Report ready").pipe(Expect.toBeVisible)
  yield* page.getByRole("button", { name: "Export" }).click()
  yield* page.getByText("Export ready").pipe(Expect.toBeVisible)
}, Deadline.withDefaultBudget("2 minutes"))
```

`Deadline.remaining` reads the time left before the deadline around it, so an optional step can be left out when
time is short. Outside `Deadline.within` and any operation, it's `None`:

```ts
import { Deadline, Page } from "@usestrider/browser"
import { Duration, Effect, Option } from "effect"

const placeOrder = Effect.fn("placeOrder")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Place order" }).click()
  const left = yield* Deadline.remaining
  if (Option.exists(left, Duration.isGreaterThan(Duration.seconds(5)))) {
    yield* page.getByRole("link", { name: "Download receipt" }).click()
  }
}, Deadline.within("20 seconds"))
```

## Timeouts

A `Timeout`'s `phase` says how far the operation got:

| Phase                   | The operation                                                              |
| ----------------------- | -------------------------------------------------------------------------- |
| `resolving`             | never found a matching element                                              |
| `waitingForCondition`   | found it, but it never became ready: hidden, disabled, covered, moving      |
| `dispatchedUnconfirmed` | sent the input, but couldn't confirm the result                             |
| `postcondition`         | acted, and what should follow never did, such as a navigation committing    |
| `waitingForEvent`       | waited for an event, such as a popup, that never came                       |

Before `dispatchedUnconfirmed`, nothing reached the page and retrying is safe. After it, check the page first:

```ts
import { Expect, Page } from "@usestrider/browser"
import { Effect } from "effect"

const submitOnce = Effect.fn("submitOnce")(function*(page: Page.Page) {
  yield* page.getByRole("button", { name: "Submit" }).click().pipe(
    Effect.catchTag("Timeout", (timeout) =>
      Effect.gen(function*() {
        if (timeout.phase !== "dispatchedUnconfirmed") {
          return yield* Effect.fail(timeout)
        }
        yield* page.getByText("Submitted").pipe(Expect.toBeVisible)
      }))
  )
})
```

Strider never retries input that may have reached the page. It retries only a gesture it stopped before the page
saw it, such as a click that would have hit a toast.

## Operations of your own

With `Effect.fn`, a timeout inside your helper is the step's own, such as the click's, and says nothing of the
steps before it. `Operation.fn` gives the caller one `Timeout`, named for the helper, whose `diagnostics.progress`
lists each step:

```ts
import { Deadline, Operation, Page } from "@usestrider/browser"
import { Console, Effect } from "effect"

const checkout = Operation.fn("checkout")(
  function*(page: Page.Page, confirmed: Effect.Effect<string>) {
    yield* page.getByLabel("Card number").fill("4242 4242 4242 4242")
    yield* page.getByRole("button", { name: "Pay" }).click()
    return yield* Operation.bound(confirmed)
  },
  Deadline.within("20 seconds")
)

const logSteps = (timeout: Deadline.Timeout) =>
  Effect.forEach(
    timeout.diagnostics.progress,
    (step) => Console.error(`${timeout.operation} › ${step.step}: ${step.state}`)
  )

const pay = Effect.fn("pay")(
  function*(page: Page.Page, confirmed: Effect.Effect<string>) {
    return yield* checkout(page, confirmed).pipe(
      Effect.tapErrorTag("Timeout", logSteps)
    )
  }
)
```

- Each operation inside is a step. If the click runs out of time, the caller gets `checkout`'s `Timeout`, in the
  click's phase, and `diagnostics.progress` lists `Locator.fill` as `ok`.
- Inside the body, a step's `Timeout` is still the step's: catching one around the click catches the click's.
- A wait of your own, such as `confirmed`, isn't one of Strider's, so nothing would end it at the deadline;
  `Operation.bound` does. Past it, this `Timeout` is in the phase `postcondition`: the click went out, and the
  confirmation didn't come.

A side effect of your own, such as a call to your shop's API, is invisible to Strider. `Operation.markSent` notes
that one may have happened, so a `Timeout` from then is in the phase `dispatchedUnconfirmed` and the caller knows
not to repeat it blindly. `Operation.observe` notes why the operation isn't done yet, and the `Timeout`'s `history`
lists what it noted. Both compile only inside an operation:

```ts
import { Deadline, Operation } from "@usestrider/browser"
import { Console, Effect } from "effect"

const placeOrder = Operation.fn("placeOrder")(
  function*(
    submit: Effect.Effect<string>,
    status: (id: string) => Effect.Effect<string>
  ) {
    yield* Operation.markSent
    const orderId = yield* Operation.bound(submit)
    return yield* Operation.bound(Effect.gen(function*() {
      while (true) {
        const current = yield* status(orderId)
        if (current === "confirmed") return orderId
        yield* Operation.observe(current)
        yield* Effect.sleep("1 second")
      }
    }))
  },
  Deadline.within("1 minute")
)

const logStatuses = (timeout: Deadline.Timeout) =>
  Console.error(timeout.operation, timeout.history.map((seen) => seen.value))

const order = Effect.fn("order")(
  function*(
    submit: Effect.Effect<string>,
    status: (id: string) => Effect.Effect<string>
  ) {
    return yield* placeOrder(submit, status).pipe(
      Effect.tapErrorTag("Timeout", logStatuses)
    )
  }
)
```

`Operation.named` does for an effect what `Operation.fn` does for a function, to name part of a program without
making it a function: the caller's `Timeout` is named for it and lists its steps.

```ts
import { Deadline, Expect, Operation, Page } from "@usestrider/browser"
import { Effect } from "effect"

const checkout = Effect.fn("checkout")(function*(page: Page.Page, coupon: string) {
  const applyCoupon = Effect.gen(function*() {
    yield* page.getByLabel("Coupon").fill(coupon)
    yield* page.getByRole("button", { name: "Apply" }).click()
    yield* page.getByText("Coupon applied").pipe(Expect.toBeVisible)
  })
  yield* applyCoupon.pipe(Operation.named("applyCoupon"), Deadline.within("10 seconds"))
  yield* page.getByRole("button", { name: "Place order" }).click()
})
```
