Compute accessible names by accname's traversal rules, as Chromium and Firefox do. An `aria-labelledby` target's hidden descendants count only when the target itself is hidden, and a hidden `<label>` still names its control. A whitespace-only child keeps its space, and children that aren't `display: inline`, and `<br>`, are separated by spaces. Name from content skips descendants whose role doesn't give its text, such as a nested tree item's group or an `alert` in a heading. An embedded ARIA combobox or listbox contributes its selected options, and a `menu` nothing. CSS `content` is read for its alternative text, `attr()`, and content set on the element itself, and a hidden pseudo-element contributes nothing. Names drop soft hyphens and zero-width spaces and keep non-breaking spaces, which still match a space; snapshot names show them as spaces. Name from content follows `aria-owns`, a native `select` in a label contributes its chosen option's label, `title` no longer names a `none` or `presentation` element, and an element that lists itself in `aria-labelledby` gives its own `aria-label` there. Snapshot text includes `::before` and `::after` content. With `includeHidden`, hidden descendants count in names too.

Some names change. If an exact `name`, a `toHaveAccessibleName` expectation, or a saved snapshot relied on the old name, update it to the name the browser reports.
