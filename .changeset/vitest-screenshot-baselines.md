Add `ScreenshotBaseline.toMatch`, which compares a page's screenshot, or one element's through `area: { element }`, with a PNG baseline keyed by test file, name, browser engine, and platform. It captures until a capture matches or two in a row agree, ignores anti-aliasing, and takes `threshold`, `maxDiffPixels`, and `maxDiffPixelRatio`. Baselines follow Vitest's snapshot update state: a local run writes a missing baseline and still fails, `vitest -u` rewrites differing ones, and CI writes none. The browser part of the key is the engine of the product the browser reports (`chromium`, `firefox`, `webkit`, or `safari`, and `other_<letters>_<digest>` for any other product). A baseline name is the file name as written: lower-case letters, digits, `.`, `_`, and `-`, starting with a letter or digit; any other name fails with `InvalidName` before a capture, and `defaultPath` refuses an invalid `Key`, so distinct keys never share a baseline. A pixel mismatch writes and attaches the actual, expected, and diff images, under a directory for the test file; a size mismatch writes the actual and expected images, and a missing or invalid baseline (including one whose PNG checksums don't match) writes none. `CurrentSettings` overrides the update mode, the baseline path, and the output directory. The browser package is unchanged.
