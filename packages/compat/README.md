# Compat: other projects' browser tests, run with Strider

A private package of browser tests ported from other projects (Playwright's and Puppeteer's suites so far), with a
ledger of every upstream test and what Strider expects of it. It's for finding bugs: a run reports each result the
ledger doesn't expect. It doesn't gate anything, and runs only when asked.

```sh
clutch lock browser -- pnpm compat oopif          # port files whose path contains "oopif", every browser they run on
STRIDER_COMPAT_BROWSERS=firefox pnpm compat       # every port on Firefox
pnpm compat:ledger status                         # how much of each source is ported
pnpm compat:ledger todo playwright 'tests/page/**' # what's left, by file
pnpm compat:ledger show playwright CL-112         # one upstream test: where, its annotations, and its expectation
pnpm compat:ledger check                          # the ledger holds together (also in pnpm test --run)
```

`pnpm compat` runs in the integration tests' Nix environment, with their pinned browsers, one file at a time. On a
machine others use, hold the browser lock (`clutch lock browser --`) and run only the files you're working on. A port
you're writing runs on Chromium there (`STRIDER_COMPAT_BROWSERS=chromium`): other work waits on the lock, and the CI
run covers every browser. Full
runs go to CI: dispatch `.github/workflows/compat.yml` (`gh workflow run compat.yml --ref <branch>`), which splits
each browser's files into shards by their recorded times and puts the merged report in the run's summary.

Each run writes `.data/compat/runs/<run>/run.json` and `report.md`, and a failed test's trace goes to
`.data/compat/traces/<run>/<browser>/`. `STRIDER_COMPAT_RUN` names the run; `STRIDER_COMPAT_OUTPUT` moves both.

## The ledger

- `sources/sources.json`: each source, its pinned revision and license, and why it's worth porting. Sources marked
  `planned` aren't indexed yet.
- `ledger/<source>.json`: every test in the pinned checkout, one a line, generated by
  `pnpm compat:ledger index <source> <checkout>`. A Playwright test is keyed by the ID its title starts with
  (`OO-001`), a Puppeteer test as Puppeteer's runner names it (`[oopif.test] OOPIF should report oopif frames`). The
  index keeps each test's leading `it.skip`/`it.fixme` calls and Puppeteer's own expectations, which say where
  upstream fails too. Re-indexing at a new revision lists the ported tests that changed upstream.
- `ledger/expectations/`: what Strider expects of each test that doesn't simply pass, as Puppeteer's ledger does. A
  port's tests have their own file, `ledger/expectations/<source>/<the port's path>.json`
  (`playwright/page/page-dialog.json` for `ports/playwright/page/page-dialog.test.ts`), an array of entries that
  name `tests` (keys, `*` matching anything), optionally `browsers`, and a `status`. Entries over whole files, such
  as Playwright's inspector, are in `general.json`, with `source` and `files` (globs).

  | Status              | Means                                                              | Names            |
  | ------------------- | ------------------------------------------------------------------ | ---------------- |
  | `fails`             | ported, and fails for a bug in Strider                             | `issue`          |
  | `needsFeature`      | can't be ported until Strider has the API                          | `issue`/`matrix` |
  | `differentByDesign` | Strider decided otherwise                                          | `decision`       |
  | `notApplicable`     | tests what Strider doesn't have or shouldn't, such as an inspector | `reason`         |

  A `decision` is a heading of `docs/decisions.md`, or the bold sentence that opens a decision's paragraph, and the
  check holds it to that. A browser that lacks what a test needs (stock WebKit's missing file chooser) is a
  `needsFeature` entry with `browsers` set, not a deliberate difference.
  A port's own entries come first, and the first entry that covers a test on a browser applies. A test with none is
  expected to pass.
- `ledger/timings.json`: each port file's last time on each browser, for planning shards. Record a run's with
  `pnpm compat:ledger timings <run>`.

## Porting a file

A port file mirrors its original's path: `ports/playwright/page/page-click.test.ts` ports
`tests/page/page-click.spec.ts`, and `ports/puppeteer/oopif.test.ts` ports `test/src/oopif.test.ts`. It calls
`upstream`, and registers each test by its key; the test's name comes from the index. The example is `ports/playwright/library/chromium/oopif.test.ts`;
the harness's relative path depends on how deep a port file is.

```ts
import { assert } from "@effect/vitest"
import * as Effect from "effect/Effect"
import { frameCount } from "../../../harness/playwright.ts"
import { upstream } from "../../../harness/upstream.ts"

upstream(import.meta.filename, {
  browsers: ["chromium"],
  launch: { chromium: { args: ["--site-per-process"] } }
}, (test) => {
  test("OO-001", ({ page, server }) =>
    Effect.gen(function*() {
      yield* page.goto(server.PREFIX + "/dynamic-oopif.html", { waitUntil: "load" })
      assert.strictEqual(yield* frameCount(page), 2)
    }))
})
```

`page` is a fresh 1280×720 page in a fresh context (`{ page: false }` opens none), and each test has Playwright's 30
seconds: a deadline over Strider's operations, and a second later an end to the test, for a wait of the port's own
that hangs. `server` is the fixture server, named as Playwright's and Puppeteer's are (a received request has its parsed `headers`, which Node merges or drops for repeats, and its `rawHeaders`, which keep every field as sent; assets are served uncached, except Puppeteer's `cached/` ones, which are cacheable and answer `If-Modified-Since` with a 304, as Puppeteer's server does): `PREFIX` is `localhost` and
`CROSS_PROCESS_PREFIX` is `127.0.0.1`, two sites, so a frame from one in a page from the other runs out of process.
It accepts WebSockets on the paths theirs do (`onceWebSocketConnection`, `sendOnWebSocketConnection`,
`waitForWebSocket`, `waitForUpgrade`). It serves only vendored assets: `pnpm compat:ledger vendor playwright <checkout> grid.html digits/0.png` copies them
into `sources/playwright/assets` with their SHA-256. A test whose title is computed, as in a loop, registers each
expansion with `{ variant }`.

The rules:

- **Keep every assertion and every step.** Translate each into Strider's API. Where Strider has no equivalent, either
  express the same check another way and say so in a comment where it happens, as the file's header lists, or don't
  port the test and mark it `needsFeature` with the Playwright matrix row (`scripts/playwright-matrix/rows`) for
  what's missing. Never loosen a check to make it pass.
- **Port what fails.** A failure is what the harness is for. A failure stays in the run's results until it's triaged, and
  gets a `fails` entry once it has an issue.
- **Don't change the page under test.** Where the original reads a page global (`window.__clicked`), read it with
  `page.evaluateInMainWorld`, through `document.querySelector("iframe").contentWindow` for a same-origin frame. Never
  make the page's own handlers write markers for the port to read.
- **Assert on Strider's errors, not Playwright's wording.** Where the original checks an error's message, check
  Strider's typed reason and that its message says what the original's says.
- **No retries, no sleeps, no longer timeouts.** Wait as the original waits, on a condition. A fixed wait the
  original makes itself, such as `page.waitForTimeout(100)` to let an action start, is ported as written, with a
  comment; none is added.
- **Upstream's own skips aren't ours.** Port an `it.fixme` or a browser `it.skip` too: Playwright's and Puppeteer's
  Firefox and WebKit aren't the stock browsers Strider drives.
